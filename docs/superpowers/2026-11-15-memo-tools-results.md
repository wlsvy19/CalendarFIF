## 한 일

- **DesktopCal 분석:** 설치된 PC 버전의 화면 정의(`app\dkappcal\resource.zip`의 Lua와 XML)와 한국어 문구(`language\kor.xml`)의 복사본을 글로만 읽었다. `calendar.db`는 열지 않았다. 기록은 `build\desktopcal-memo-research.md`(git 밖). 메모 편집 창의 도구는 완료, 텍스트 색상/셀 색상, 작업 반복, 알림, 기념일까지 카운트다운, 기록 보기다. "타이머"는 카운트다운(D-day)이다. 셀 설정은 넘버링, 셀 간격, 줄 간격, 완료 작업 두 가지, 알림 시각 표시, 효과음 둘(편집 완료 알람, 리마인드 알람)이다.
- **편집 화면:** 늘 펼쳐져 있던 배경색 줄을 없애고 아래에 도구 단추 넷(완료, 배경, 알림, 카운트다운)을 두었다. 배경은 색 상자에서 고르고 고른 색이 메모 칸 바탕에 보인다. 위쪽 띠에 그날의 알림과 카운트다운이 칩으로 보이고 누르면 고친다. 메모 칸은 도구 줄까지 채운다.
- **알림:** 글, 시각, 미리 알림(당일~일주일 전, 다섯 개까지), 반복(안 함, 매일, 근무일, 매주, 매달, 매년, 음력 매년)과 끝(계속, 날짜까지, 횟수), 완료. 삭제는 두 번 눌러야 한다.
  - 웹앱이 열려 있으면 화면 위쪽 상자와 소리로 알린다(아이폰은 화면을 한 번 누른 뒤부터 소리가 난다). 상자를 누르면 그 날짜를 연다(편집 중이면 고친 것을 저장하고 넘어간다).
  - PC 앱은 화면 오른쪽 아래에 맨 위로 뜨는 작은 창과 소리로 알린다. 창이 먼저 뜨고 소리는 그 뒤에 난다.
  - 아이폰에서 앱이 닫혀 있을 때는 Scriptable 위젯 스크립트가 돌 때마다 앞으로 7일의 알림을 가까운 것부터 48개까지 아이폰 알림으로 예약한다. 알림 시트의 `지금 예약`은 저장해 서버에 닿은 것을 확인한 뒤 `Scriptable 열기` 링크로 바뀌고, 그것을 누르면 바로 예약한다. 위젯에서 로그아웃하면 예약을 지운다.
  - 기기마다 울린다. 같은 기기에서 같은 알림은 한 번만 울린다(시각을 바꾸면 다시 울린다). 10분 넘게 늦은 것은 울리지 않는다.
- **카운트다운:** 유형(기본, 생일(나이), 기념일, 명절, 시험), 반복(안 함, 매년, 음력 매년), `달력 아래에 표시`. 달력 아래 줄에 "글 3일 남음", "오늘", "N일 지남"으로 가까운 순서로 보인다.
- **달력 칸:** 그날의 알림(종과 시각)과 카운트다운(모래시계, 생일은 케이크)을 메모 줄 앞에 적는다.
- **셀 설정:** 웹앱 설정에 `셀` 묶음(줄 머리, 셀 간격, 줄 간격, 완료된 작업 표시, 완료 작업 맨 아래로, 알림 시각 표시, 편집 완료 알람, 리마인드 알람). PC 앱의 셀 쪽에 알림 시각 표시와 리마인드 알람을 더했다.
- **자료와 동기화:** 알림과 카운트다운은 달 문서 밖의 새 문서 하나(`users/{uid}/data/events`)에 둔다. 옛 앱(PC 0.6.0, 옛 위젯)이 달 문서를 써도 닿지 않는다. 쓰기는 트랜잭션으로 서버 값과 비교해서 하므로, 오래된 오프라인 변경이 다른 기기의 새 변경을 덮거나 다른 기기에서 지운 항목을 되살리지 않는다. 보내지 못한 변경은 브라우저 저장소에 남았다가 연결되면 보낸다.
- **소리:** 직접 합성한다(완료, 차임, 벨). DesktopCal의 소리 파일은 쓰지 않았다.

## PC 앱 꾸리기

사용자가 `release`에 `CalendarFIF.exe` 파일 하나만 두라고 했다. 하려던 일: `electron-builder`(무료 빌드 도구, 개발용 의존성)로 지금의 앱 폴더를 한 파일짜리 실행 파일(portable)로 묶어 `release\CalendarFIF.exe`에 두고, 새 버전마다 그 파일을 바꾸고 옛 폴더를 지우며, Windows 시작 프로그램이 그 파일을 가리키게 한다. 한 파일짜리는 켤 때마다 안의 파일을 풀어서 몇 초 늦게 켜진다. 이 일을 맡긴 에이전트를 이 환경의 자동 권한 검사가 두 번 막았다("Unauthorized Access", 그다음 "Undermining Oversight"). 새 도구를 내려받아 설치하는 것, 사용자의 앱을 바꾸는 절차를 자동으로 만드는 것 중 어느 것이 걸렸는지는 모른다. 더 돌아가지 않고 사용자에게 묻는다. 작업 지시서는 git 밖의 `.superpowers/sdd/2026-11-15-memo-tools/task-13-brief.md`에 있었다(작업 공간을 지우기 전에 이 문서에 옮겨 적었다).

## 그 뒤: 아이폰 잠금 화면 알림이 오지 않는다 (2026-11-15 오후)

사용자: "아이폰 잠그일때 뜨는알람 그거는 안돼"

- 알림을 예약하는 코드(`src/widget/alarms.ts`, `main.ts`)와 Scriptable의 문서를 다시 맞춰 보았지만 틀린 곳은 찾지 못했다. 이 PC에서는 아이폰의 알림을 볼 수 없어 원인을 가리지 못했다. 생각할 수 있는 원인: 위젯 스크립트를 0.7.0으로 다시 복사하지 않았다, 아이폰에서 Scriptable의 알림이 꺼져 있다(또는 잠금 화면 표시가 꺼져 있거나 알림 요약, 집중 모드), 스크립트 이름이 `CalendarFIF`가 아니라 `Scriptable 열기`가 다른 것을 연다, 알림을 만든 뒤 위젯이 아직 새로 그려지지 않았다.
- Scriptable의 문서는 알림이 꺼져 있을 때 `schedule()`이 어떻게 되는지 말하지 않는다. 오류 없이 끝나고 예약이 남지 않을 수 있어서, 지금까지는 메뉴에 "알림 N개 예약됨"이 나와도 실제로 예약됐는지 알 수 없었다.
- 그래서 위젯 스크립트 0.7.1에서 원인을 아이폰에서 바로 가릴 수 있게 했다.
  - 예약한 뒤 `Notification.allPending()`으로 다시 읽어 실제로 남은 수를 메뉴 제목에 쓰고, 메뉴 글에 다음 알림(날짜, 시각, 글)을 보인다. 예약했는데 남지 않았으면 "알림을 예약했지만 아이폰에 남지 않았습니다"와 함께 설정 → 앱 → Scriptable → 알림에서 `알림 허용`과 `잠금 화면`을 켜라고 한다.
  - 메뉴에 `시험 알림 (1분 뒤)`를 더했다. 1분 뒤에 울리는 알림(이름 `calfif-test`, 예약 고르기가 지우지 않는다)을 예약하고 남았는지 확인한다(남았다 / 남지 않았다 / 확인하지 못했다). 화면을 잠그고 기다리면 잠금 화면에 와야 한다.
  - 서버에서 알림 문서를 읽지 못해 보관해 둔 것으로 예약했으면 그렇다고 덧붙인다(방금 만든 알림이 빠졌을 수 있다). 예약한 것보다 덜 남았으면 그것도 적는다. 앱 안에서 알림 기능이 멈춰도 15초 뒤에는 메뉴가 뜬다.
  - 웹앱의 `Scriptable 열기`(`?schedule=1`)로 열었을 때의 결과를 바로 보이는 알림 대신 상자로 보인다. 앱이 앞에 있을 때 바로 보이는 알림은 iOS가 띄우지 않을 수 있어, 눌러도 아무 일이 없는 것처럼 보였을 수 있다.
- 정한 것: 원인을 모르는 채로 예약 방식을 바꾸지 않고 먼저 확인할 수단을 넣었다. 알림이 막 울린 그 순간에 확인하면 "남지 않았습니다"가 잘못 나올 수 있는데 드물어서 두었다. → 사용자가 스크립트를 한 번 더 복사하고 메뉴를 한 번 봐야 한다. 메뉴의 단추 순서가 바뀌었다(미리 보기, 시험 알림, 로그아웃).
