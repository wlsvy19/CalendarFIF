# CalendarFIF ③ 단계 설계: PC 바탕화면 앱

작성일 2026-11-13. 전체 설계(`2026-11-13-calendar-sync-design.md`)의 8.3절을 구체화한 문서다. 사용자가 자리를 비우면서 "알아서 계속 만들라"고 했기 때문에 화면 시안 확인 없이 작성자가 정했다. 작성자가 정한 것은 14절에 모아 두었고, 사용자가 돌아와서 바꿀 수 있다.

## 1. 무엇을 왜 만드는가

사용자는 PC에서 DesktopCal을 바탕화면에 띄워 놓고 쓴다. ① 단계가 끝난 지금 아이폰에서 고친 내용은 DesktopCal에 나타나지 않고, DesktopCal에서 고친 내용은 따라가기 창을 켜 두어야 넘어간다. PC에서도 양방향이 되려면 DesktopCal 자리에 CalendarFIF가 떠 있어야 한다.

사용자가 말한 것(2026-11-13):

- "pc에서 사용할떄 웹브라우저로 띄우는게 아니라, 바탕화면에 데스크탑캘린더 처럼 띄우는거를 나는원한건데"
- "뒷바탕이 투명으로 되면서"
- "데스크탑캘린더에 있는 설정들은 최대한 모두 넣었으면 좋겠어"
- "모바일로 확인해보니까 달력넘길때 부드럽지 않더라고. 이런거 까지 다 고려해"

## 2. 목표, 범위 밖, 실패 조건

### 목표

- **D1.** 달력이 바탕화면에 붙어 있다. 다른 창 뒤에 머물고, "바탕화면 보기"(Win+D)를 해도 남아 있고, 작업 표시줄과 Alt+Tab에 나타나지 않는다.
- **D2.** 배경이 투명하다. 바탕화면 그림이 날짜 칸 뒤로 비쳐 보이고, 투명한 정도를 설정에서 바꾼다.
- **D3.** 여기서 고친 메모와 배경색이 아이폰에 보이고, 아이폰에서 고친 내용이 여기에 보인다. 동기화 코드는 웹앱과 같은 것을 쓴다.
- **D4.** 위치와 크기를 바꿀 수 있고 기억한다. 모니터 구성마다 따로 기억한다.
- **D5.** 트레이 아이콘, Windows 시작 시 실행, 중복 실행 방지, 보이기/숨기기, 내용만 숨기기.
- **D6.** DesktopCal의 설정 가운데 서버·유료·메모지와 무관한 것을 최대한 넣는다(8절).
- **D7.** 아이폰 웹앱에서 달을 넘길 때 손가락을 따라 움직이고 매끄럽게 넘어간다(10절).

### 범위 밖

- 알림과 반복 일정, 스티커 메모, 카운트다운 카드, 스킨과 배경 사진, 글자색 태그, 검색, 가져오기·내보내기 메뉴, 자동 업데이트, 언어 선택.
- DesktopCal을 지우거나 끄는 일. 사용자가 전환을 정한다.
- 아이폰 위젯(② 단계).

### 실패 조건

- 다른 창을 가리거나, 클릭할 때마다 앞으로 튀어나와 작업을 방해한다.
- 탐색기(Explorer)를 불안정하게 만든다.
- 동기화 규칙이 웹앱과 달라진다.

## 3. 조사한 것

### DesktopCal이 쓰는 방식 (실행 중인 창을 읽기만 해서 확인)

- 이 PC는 Windows 11 Enterprise 빌드 26200이다. 바탕화면은 최상위 창 `Progman` 아래에 `SHELLDLL_DefView` → `SysListView32`(아이콘)와 `WorkerW`(배경 그림)가 있는 구조다.
- DesktopCal은 `dkdockexplorerx64.dll`을 탐색기 프로세스에 끼워 넣는다.
- DesktopCal의 달력 창은 최상위 팝업 창이고, 바탕화면 아이콘 창을 소유자(owner)로 두며, 층 창(`WS_EX_LAYERED`)으로 투명하게 그리고, 도구 창(`WS_EX_TOOLWINDOW`)이라 작업 표시줄에 나타나지 않는다. Z 순서에서 `Progman` 바로 위에 있다.

### 이 PC에서 한 실험 (Electron 45.3.1, koffi 3.3.8)

- 테두리 없는 투명 창을 만들고(`frame: false`, `transparent: true`, `skipTaskbar: true`), 창의 소유자를 `Progman`으로 바꾸고(`SetWindowLongPtrW(hwnd, GWLP_HWNDPARENT, progman)`), Z 순서 맨 아래로 보냈다(`SetWindowPos(hwnd, HWND_BOTTOM, …, SWP_NOACTIVATE)`).
- 결과: 창이 `Progman` 바로 위에 자리 잡았다. 바탕화면 그림과 아이콘이 반투명한 칸 뒤로 비쳐 보였다. "바탕화면 보기" 상태에서도 창이 남아 있었다.
- 아직 확인하지 못한 것: 클릭했을 때 앞으로 올라오는 정도, 탐색기를 다시 시작했을 때, 모니터가 두 대일 때.

## 4. 검토한 방식과 고른 방식

| 방식 | 장점 | 문제 | 결과 |
|---|---|---|---|
| A. 소유자를 `Progman`으로 둔 투명 창을 맨 아래에 둔다 | 이 PC에서 실험으로 확인했다. DesktopCal의 창과 같은 구조다. 탐색기를 건드리지 않는다. | 소유자 창이 없어지면(탐색기 재시작) 창도 없어지므로 다시 만들어야 한다. 클릭하면 앞으로 올라오려 하므로 다시 내려 보내야 한다. | **선택** |
| B. 바탕화면 창의 자식 창으로 넣는다(`SetParent`) | 아이콘 뒤에 둘 수 있다 | 다른 프로세스의 자식 창에서는 Electron의 투명 그리기가 검게 나오는 사례가 많다. Windows 11 24H2에서 바탕화면 창 구조가 바뀌어 기존 기법이 깨졌다. | 탈락 |
| C. 그냥 맨 아래에 두는 일반 창 | 가장 단순하다 | "바탕화면 보기"를 하면 사라진다 | A가 안 될 때의 대안 |
| D. 탐색기에 모듈을 끼워 넣는다 (DesktopCal 방식) | 바탕화면과 완전히 한 몸이 된다 | 탐색기를 불안정하게 만들 수 있고 보안 프로그램이 막는다. 만들기도 어렵다. | 탈락 |

## 5. 구조

```
src/desktop/        Electron 메인 프로세스 (창, 바탕화면 붙이기, 트레이, 단축키, 설정 파일)
src/desktop/preload Electron과 화면 사이의 좁은 통로 (window.calfifDesktop)
src/web/            화면. 웹앱과 같은 코드를 "desktop" 모드로 빌드해서 쓴다
src/sync, src/core  동기화와 규칙. 그대로 쓴다
```

- 화면은 `vite build --mode desktop`으로 `dist-desktop/`에 만들고, 앱 안의 `app://calfif/` 주소로 읽는다. 호스팅 주소에 기대지 않는다. 고정된 주소가 있어야 로그인 상태와 오프라인 캐시(IndexedDB)가 유지된다.
- desktop 모드에서는 서비스 워커를 등록하지 않는다. 파일이 앱 안에 있어서 필요 없다.
- Windows API 호출은 `koffi`로 한다(미리 빌드된 바이너리, 컴파일러가 필요 없다). `src/desktop/win32.ts` 한 파일에 모은다.
- 메인 프로세스와 화면은 `contextBridge`로 노출한 `window.calfifDesktop`만으로 이야기한다. 화면에서 Node를 쓰지 않는다(`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`).
- Firebase 설정값은 웹앱과 같은 `.env.local`에서 빌드할 때 들어간다. 로그인은 앱 안의 로그인 화면에서 사용자가 한다.
- 설정은 두 곳에 둔다. 달력 모양에 관한 것은 화면 쪽 저장소(`localStorage`)에, 창과 시스템에 관한 것은 메인 프로세스의 `settings.json`(`%APPDATA%\CalendarFIF`)에 둔다. 둘 다 기기별이고 동기화하지 않는다.

## 6. 창의 동작

- **붙이기**: 창을 만든 뒤 소유자를 `Progman`으로 바꾸고 맨 아래로 보낸다. `Progman`을 찾지 못하면 4절의 C 방식으로 띄운다.
- **앞으로 올라오지 않기**: 평소에는 활성화되지 않는 창(`focusable: false`)으로 둔다. 날짜를 더블클릭해 편집을 시작할 때만 활성화를 허용하고, 편집을 끝내면 다시 끄고 맨 아래로 보낸다. 창이 활성화되거나 Z 순서가 바뀔 때마다 맨 아래로 다시 보낸다.
- **탐색기 재시작**: 창이 예기치 않게 닫히면 `Progman`이 다시 생길 때까지 1초 간격으로 기다렸다가 창을 다시 만들고 붙인다. 화면 구성이 바뀔 때(`display-added`, `display-removed`, `display-metrics-changed`)는 위치를 다시 맞춘다.
- **위치와 크기 조정**: 평소에는 움직이지 않는다. 메뉴의 "위치 및 크기"를 고르면 조정 상태가 된다. 조정 상태에서는 창을 끌어 옮기고 가장자리를 끌어 크기를 바꾼다. 화면 위쪽에 "적용"과 "취소"가 보인다. 화면 밖으로 완전히 나가게 둘 수 없다.
- **모니터**: 창의 위치와 크기를 모니터 구성(각 모니터의 좌표와 크기를 이은 문자열)마다 따로 기억한다. 처음 보는 구성에서는 주 모니터가 아닌 모니터가 있으면 그 모니터의 오른쪽에, 없으면 주 모니터의 오른쪽에 화면 높이에 맞춰 띄운다. 기본 크기는 화면 작업 영역의 폭 65%, 높이 96%다(사용자의 DesktopCal이 1920×1032 작업 영역에서 1260×992를 쓰고 있다).
- **보이기와 숨기기**: 달력 전체를 숨기거나, 칸은 두고 글만 숨긴다. 트레이 메뉴와 단축키로 한다.
- **맨 위에 보기**: 켜면 달력을 다른 창 위로 올린다(`setAlwaysOnTop`). 끄면 다시 바탕화면에 붙인다.
- **중복 실행 방지**: 두 번째 실행은 첫 번째 창을 보이게 하고 끝난다.

## 7. 화면

- 바탕은 완전히 투명하다. 날짜 칸은 반투명한 배경 위에 글자를 쓴다. 글자에는 그림자를 넣어 밝은 배경 그림 위에서도 읽힌다.
- 제목 줄에는 연·월, 이전, 오늘, 다음, 메뉴 단추가 있다. 설정으로 숨길 수 있다.
- 날짜 칸을 **더블클릭**하면 편집 화면이 그 창 안에 뜬다(웹앱의 편집 화면과 같은 기능: 메모, 완료 표시, 배경색). 한 번 클릭으로는 아무 일도 일어나지 않는다. 칸을 오른쪽 클릭하면 "편집", "배경색", "오늘로"가 있는 작은 메뉴가 뜬다.
- 동기화 상태는 제목 줄 오른쪽에 작게 보인다.
- 달력 배치는 네 가지다(DesktopCal의 네 가지에 대응).
  - 변동 월: 오늘이 있는 주를 기준으로 지난 주 몇 줄과 앞으로의 주를 정해진 줄 수만큼 보여 준다. 기본값.
  - 전체 월: 한 달을 통째로 보여 준다. 웹앱과 같다.
  - 고정 단일 행: 이번 주 한 줄.
  - 변동 단일 행: 오늘부터 7일 한 줄.

## 8. 설정 (DesktopCal의 설정 51개와의 대응)

DesktopCal의 설정 화면은 "캘린더", "셀", "글꼴 및 색상", "고급", "메모" 다섯 쪽이다. CalendarFIF의 설정 화면도 앞의 네 쪽을 같은 이름으로 둔다.

- 색을 고르는 곳은 웹앱의 배경색 22색과 "없음", 직접 입력(16진수)을 쓴다.
- 공휴일은 날짜가 고정된 것(신정, 3.1절, 어린이날, 현충일, 광복절, 개천절, 한글날, 성탄절)과 음력으로 정해지는 것(설날 연휴, 부처님오신날, 추석 연휴)을 표시한다. 음력 계산은 브라우저에 들어 있는 달력 기능(`Intl`, `dangi` 달력)을 쓴다. 대체공휴일과 선거일은 넣지 않는다.
- 단축키 기본값은 DesktopCal의 `Ctrl+H`, `Ctrl+F`가 브라우저의 단축키와 겹쳐서 `Ctrl+Alt`를 붙였고, 기본은 꺼 둔다.

### 다음으로 미루는 것

유리 효과(창 뒤 흐림), 24절기, 최대 열 수, 편집 완료 단축키 바꾸기, 떠 있는 버튼, 날짜 선택과 월 선택 메뉴, 검색.

### 넣지 않는 것

계정·동기화·VIP·업데이트·프록시·언어·광고에 관한 것, 알림 시간과 알림 소리, 미완료 작업 자동 연기, 스티커 메모 쪽 전체, 카운트다운 카드 투명도, 스킨과 배경 사진.

## 9. 트레이, 단축키, 자동 실행

- 트레이 메뉴: 캘린더 숨기기/보이기, 내용 숨기기/보이기, 맨 위에 보기, 위치 및 크기, 설정, Windows 시작 시 실행(체크), 제품 정보, 닫기.
- 제목 줄의 메뉴 단추에도 같은 항목과 "오늘로", "로그아웃"이 있다.
- 단축키는 전역 단축키다. 등록에 실패하면(다른 프로그램이 쓰고 있으면) 설정 화면에 알린다.
- 자동 실행은 꾸린 앱에서만 건다(`app.setLoginItemSettings`). 개발 실행에서는 걸지 않는다.

## 10. 아이폰에서 달 넘기기 (웹앱 수정)

- 손가락을 가로로 끌면 달력이 손가락을 따라 움직이고, 옆 달이 따라 들어온다. 손을 떼면 넘어가거나 제자리로 돌아간다. 넘어가는 기준은 폭의 20%를 넘게 끌었거나 빠르게 튕긴 경우다.
- 움직임은 `transform`으로만 하고 200ms 안팎으로 끝낸다. 세로 스크롤과 다투지 않는다(`touch-action: pan-y`). "동작 줄이기" 설정이 켜져 있으면 미끄러지는 효과 없이 바로 바꾼다.
- 그리는 동안 레이아웃을 읽고 쓰기를 섞지 않는다(① 단계에서 미뤄 둔 항목).
- 이 수정은 PC 앱과 무관하게 웹앱에 들어가고, 다시 배포해야 아이폰에 보인다. 배포는 사용자가 돌아온 뒤에 한다.

## 11. 실행과 꾸리기

- `npm run desktop`: 화면을 desktop 모드로 빌드하고 Electron으로 띄운다(개발용, 실제 프로젝트에 붙는다).
- `npm run desktop:emu`: 에뮬레이터에 붙여 띄운다(시험용 계정으로 자동 로그인).
- `npm run desktop:pack`: `release/CalendarFIF-win32-x64/CalendarFIF.exe`를 만든다. 서명은 하지 않는다. 설치 프로그램은 만들지 않는다.
- npm 11은 설치 스크립트를 기본으로 막는다. Electron 실행 파일은 `node node_modules/electron/install.js`로 받는다. 이것을 `npm run desktop:setup`으로 묶는다.

## 12. 위험

| 위험 | 대응 |
|---|---|
| 클릭할 때 창이 앞으로 올라온다 | 평소에는 활성화되지 않는 창으로 두고, 편집할 때만 활성화한다. 그래도 올라오면 맨 아래로 다시 보낸다. |
| 탐색기가 다시 시작되면 창이 사라진다 | 닫힘을 감지해 다시 만든다. |
| 회사 PC가 서명 없는 실행 파일을 막는다 | 개발 실행(`npm run desktop`)은 이 PC에서 돌아가는 것을 확인했다. 꾸린 앱이 막히면 개발 실행을 바로가기로 쓴다. |
| 화면이 잠겨 있으면 붙은 모습을 눈으로 확인할 수 없다 | 창의 상태(소유자, Z 순서, 보임)를 Windows API로 읽어 확인하고, 모습은 사용자가 돌아와서 본다. |
| 투명 창 위에서 한글 입력기 후보 창이 어긋난다 | 사용자가 써 보고 확인한다. |

## 13. 끝났다고 보는 기준

- 달력이 바탕화면에 떠 있고 다른 창 뒤에 머문다. "바탕화면 보기"를 해도 남아 있다.
- 배경이 투명하고 투명도를 바꿀 수 있다.
- 여기서 고친 내용이 아이폰에 보이고, 아이폰에서 고친 내용이 5초 안에 여기에 보인다.
- 다시 로그인(재부팅)하면 같은 자리에 자동으로 뜬다.
- 8절 "넣는 것"의 설정이 동작한다.
- 아이폰에서 달을 넘길 때 달력이 손가락을 따라 움직인다.

## 14. 작성자가 정한 것 (사용자 확인 부탁)

1. ② 위젯보다 ③ PC 앱을 먼저 한다.
2. 창을 바탕화면에 붙이는 방식은 4절의 A다. 탐색기에 끼워 넣는 DesktopCal의 방식은 쓰지 않는다.
3. 편집은 더블클릭으로 시작한다(DesktopCal과 같다). 한 번 클릭으로는 열리지 않는다.
4. 화면 모양(칸 색, 투명도 60%, 흰 글자, 변동 월 5줄)은 시안 없이 정했다. 전부 설정에서 바꿀 수 있다.
5. 8절의 "다음으로 미루는 것"과 "넣지 않는 것"의 구분.
6. 단축키는 기본으로 꺼 둔다.
7. 꾸린 앱은 설치 프로그램 없이 폴더 하나로 만든다.
8. 설정은 기기마다 따로 두고 동기화하지 않는다.
