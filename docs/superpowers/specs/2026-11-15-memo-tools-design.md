# 메모 편집 도구, 알림, 카운트다운, 셀 설정 설계

2026-11-15. 사용자의 요청:

1. "메모장열었을때, 배경을 이렇게 나오는게 하니라 캘린데스크더 앱 의 메모 참고해서 만들어 보면 체크표시, 배경고르는거 , 있고 알람도 있어. 그리고 타이머도 있어."
2. "그리고 셀설정하는것도있어 이거 찾아분석하고 만들어"

사용자는 2026-11-14에 "앞으로 남은작업. 나한테 물어보지말고 너가 알아서 진행쭉 해."라고 했다. 그래서 이 설계는 묻지 않고 작성자가 정했다. 정한 것은 11절에 틀렸을 때의 비용과 함께 적었고, 모두 사용자가 바꿀 수 있다.

## 1. 조사

이 PC에 설치된 DesktopCal 3.32의 화면 정의(`app\dkappcal\resource.zip`의 Lua와 XML)와 한국어 문자열(`language\kor.xml`)의 복사본을 글로만 읽었다. `calendar.db`는 열지 않았고 아무것도 실행하지 않았다. 아이폰 앱(CalendarTask)은 App Store의 공개 페이지만 봤다. 조사 기록은 `build\desktopcal-memo-research.md`(git 밖)에 있다.

- **메모 편집 창(PC):** 위에 그날 걸린 일정(반복, 알림, 카운트다운) 띠가 있고, 가운데에 한 줄에 일 하나씩 적는 글 상자가 있고, 아래에 도구 단추 여섯 개가 있다: `작업 완료 표시`(지금 줄을 완료로), `텍스트 색상/셀 색상`(글자색과 배경색 고르기, 22색 + 없음 + 사용자 색 + 최근 색), `작업 반복`, `알림`, `기념일까지 카운트다운`, `기록 보기`(유료).
- **완료:** 줄 맨 앞의 `[+]`가 완료이고 취소선으로 그린다. 우리 형식과 같다. 완료할 때 효과음이 날 수 있다.
- **알림:** 시각(시 0~23, 분), 미리 알림(당일, 하루 전, 이틀 전, 사흘 전, 5일 전, 일주일 전, 사용자 정의 0~30일 중 1~5개), 반복(15가지)과 끝(무제한, 날짜, 횟수), `읽음으로 표시`. 울리면 맨 위에 뜨는 작은 창이 시각과 글을 보여 주고 `확인` 단추 하나가 있다. 다시 알림은 없다. 소리는 설정의 `리마인드 알람`이다.
- **"타이머":** 정체는 `기념일까지 카운트다운`이다. 날짜까지 남은 날(지난 날)을 세는 D-day다. 유형 다섯(카운트다운, 생신(나이 표시), 기념일, 제전, 시험), 반복(매년, 음력 매년 등), `카드로 표시`(바탕화면 카드)와 `달력 하단에 표시`를 켜고 끈다. 글은 "%d일 남음", "%d일 경과", "오늘".
- **셀 설정(설정의 `셀` 쪽):** 넘버링(없음, 번호, 점), 셀 간격, 줄 간격, 완료 작업 맨 아래로, 완료된 작업 표시, 알림 시각 표시, 미완료 작업 30일 자동 연기(유료), 효과음 둘(편집 완료 알람, 리마인드 알람). 아이폰 앱의 `셀` 목록은 공개된 곳이 없어서 PC의 이 쪽을 기준으로 삼는다.
- 알 수 없는 것: DesktopCal이 반복과 알림을 DB에 적는 형식, 줄 배경색의 형식, 셀 간격과 줄 간격의 값 범위, 에빙하우스 반복의 날짜.

지금 CalendarFIF의 편집 화면은 위에 `배경색` 동그라미 줄이 늘 펼쳐져 있고, 아래에 메모 칸과 `완료 표시` 단추가 있다. 알림과 카운트다운은 없다. PC 앱의 설정에는 `셀` 쪽(줄 머리, 셀 간격, 줄 간격, 완료 작업 두 가지, 편집 완료 알람)이 이미 있고, 웹앱의 설정에는 셀에 관한 것이 `보기` 묶음에 섞여 있다.

## 2. 목표

- 편집 화면을 DesktopCal의 메모 편집 창처럼 바꾼다: 위에 그날의 알림과 카운트다운 띠, 가운데에 메모, 아래에 도구 단추(완료, 배경, 알림, 카운트다운). 배경색은 단추를 눌러 고르고, 고른 색은 메모 칸의 바탕에 바로 보인다.
- 알림을 만든다: 날짜와 시각, 미리 알림, 반복, 완료. PC 앱은 정한 시각에 맨 위에 작은 창을 띄우고 소리를 낸다. 아이폰은 Scriptable이 기기 알림을 예약한다. 웹앱이 열려 있으면 화면 안에서도 알린다.
- 카운트다운을 만든다: 유형, 반복, 달력 아래 표시. 달력 아래 줄에 "시험 3일 남음"처럼 보인다.
- 달력 칸에 그날의 알림과 카운트다운을 메모 줄 앞에 작은 표시와 함께 적는다.
- 웹앱 설정에 `셀` 묶음을 만들고 PC의 `셀` 쪽에 없는 것을 더한다.
- 웹앱과 PC 앱과 위젯이 같은 자료를 쓰고 동기화한다.

## 3. 하지 않는 것

- 글자색(줄마다의 텍스트 색상). 글 상자를 서식 있는 편집기로 바꿔야 한다. 사용자는 배경을 말했다.
- `작업 반복`(달력에 되풀이해 나오는 할 일). 알림과 카운트다운의 반복만 만든다.
- `기록 보기`, 미완료 작업 자동 연기, 카운트다운 카드(바탕화면에 따로 뜨는 창), 사용자 정의 미리 알림 시각, 다시 알림.
- DesktopCal에 있는 알림과 카운트다운 가져오기(형식을 모른다).
- 위젯 칸에 알림과 카운트다운 적기(위젯은 알림 예약만 한다).
- 돈이 드는 것: Cloud Functions(Blaze), 유료 푸시 서비스, 새 계정이 필요한 외부 서버.

## 4. 지켜야 할 것

- 비용 0원, Firebase Spark만. 달 문서(`users/{uid}/months/{YYYY-MM}`)의 형식과 병합 규칙, `src/core/merge.ts`와 `src/sync`의 기존 파일은 바꾸지 않는다(새 파일은 더해도 된다).
- 옛 앱(사용자가 켜 둔 PC 앱 0.6.0, 아직 바꾸지 않은 위젯 스크립트)이 새 자료를 망가뜨리지 않는다. 그래서 새 자료는 달 문서 밖의 새 문서에 둔다.
- 손가락으로 넘기기와 편집 화면 열기의 부드러움(2026-11-15에 잰 값)을 나쁘게 하지 않는다. 쪽 서명에 알림·카운트다운을 넣어 바뀌지 않은 쪽은 다시 그리지 않는다.
- 사용자의 실제 메모와 알림 글을 로그, 테스트, 저장소에 넣지 않는다. 테스트 자료는 지어낸 것만 쓴다.
- DesktopCal의 코드, 그림, 소리 파일을 쓰지 않는다. 소리는 직접 합성한다.

## 5. 접근

- **아이폰 알림:** (가) Scriptable이 알림을 예약(공짜, 이미 쓰는 앱, 위젯이 돌 때와 스크립트를 열 때 예약) (나) 웹 푸시를 보내는 서버를 Cloudflare Workers 무료 요금으로 두기(정확하지만 새 계정과 설정이 필요) (다) GitHub Actions 예약 실행으로 푸시(5분 단위에 몇십 분씩 늦을 때가 있어 알림으로 못 쓴다). **(가)로 한다.** 웹앱이 열려 있을 때는 화면 안에서도 알린다. (나)는 (가)로 부족하면 나중에 더할 수 있게 자료를 둔다.
- **저장:** (가) 날짜 칸 기록(달 문서)에 넣기 (나) 새 문서 하나에 모두 넣기. 옛 앱이 날짜를 지우면 함께 지워지고, 알림을 예약하려면 모든 달을 읽어야 하므로 **(나)로 한다.** 문서 하나라 위젯이 한 번 읽어서 예약할 수 있다.
- **편집 화면:** (가) 지금의 글 상자를 그대로 두고 도구 단추를 더함 (나) 서식 있는 편집기. 글자색을 하지 않으므로 **(가)로 한다.** 아이폰의 한글 입력이 그대로 안전하다.

## 6. 자료

### 6.1 문서

`users/{uid}/data/events` 문서 하나:

```
{ items: { <id>: EventRecord, ... }, updatedAt: <서버 시각> }
```

- `id`: 20자 무작위(영숫자). 만든 기기가 정한다.
- `EventRecord`:
  - `type`: `'alarm' | 'countdown'`
  - `date`: `'YYYY-MM-DD'`. 알림은 처음 울릴 날, 카운트다운은 그날(생일은 태어난 날).
  - `text`: 글, 1~200자.
  - `done`: 완료(읽음으로 표시). 완료한 알림은 울리지 않고, 완료한 카운트다운은 달력 아래 줄에서 빠진다.
  - `repeat`: `{ freq, until?, count? }`. `freq`는 `'none' | 'daily' | 'workday' | 'weekly' | 'monthly' | 'yearly' | 'lunarYearly'`. `until`은 `'YYYY-MM-DD'`(그날까지 포함), `count`는 1~99999회. 둘 다 없으면 끝이 없다.
  - 알림만: `time` `'HH:MM'`, `advance` 미리 알림 일수의 배열(0, 1, 2, 3, 5, 7 중 1~5개, 오름차순).
  - 카운트다운만: `kind` `'basic' | 'birthday' | 'anniversary' | 'holiday' | 'exam'`, `showBottom` 불.
  - `editedAt`(밀리초), `editedBy`(기기 이름, 달 문서와 같은 값).
- 쓰기는 `set(merge)`로 `items.<id>` 하나만 바꾸거나 `deleteField()`로 지운다. 서로 다른 항목은 두 기기에서 동시에 바꿔도 섞이지 않고, 같은 항목은 늦게 쓴 쪽이 이긴다.
- 읽을 때 형식이 틀린 항목은 버린다. 모르는 칸은 버리지 않고 그대로 두지도 않는다(다시 쓸 때 우리 형식으로 쓴다).

### 6.2 보안 규칙

`match /users/{uid}/data/{docId}`: `docId == 'events'`이고 달 문서와 같은 조건(본인, 관리자거나 사용 허가가 켜진 사용자)일 때 읽고 쓴다. 규칙이 바뀌므로 배포는 둘로 나눈다(규칙, 2분 뒤 웹앱).

### 6.3 동기화

`src/sync/eventsDoc.ts`(읽기와 쓰기 내용 만들기, 순수 함수)와 `src/web/eventsStore.ts`(구독, 보내지 않은 변경, 알림):

- 문서를 구독하고, 보내지 않은 변경을 브라우저 저장소(`calfif.eventsPending`)에 두었다가 연결되면 보낸다. 보낸 것이 문서에 보이면 지운다.
- 화면에 보이는 값 = 서버 값 위에 보내지 않은 변경. 변경이 바뀌면 `version`을 올리고 듣는 쪽에 알린다.
- 로그인한 사용자가 바뀌면 비운다(달 자료와 같은 때).

### 6.4 반복과 울릴 때 (순수 함수, `src/core/events.ts`)

- `occurrences(rec, from, to)`: `from`~`to`(날짜 포함) 사이에 걸리는 날짜.
  - `daily` 매일, `workday` 월~금 중 공휴일이 아닌 날(`holidays.ts`), `weekly` 같은 요일, `monthly` 같은 날(그날이 없는 달은 건너뜀), `yearly` 같은 월일(2월 29일은 윤년에만), `lunarYearly` 같은 음력 월일(그해에 그 음력 날이 없으면 건너뜀, `lunar.ts`의 표 범위 밖이면 없음).
  - `until`과 `count`(처음 날부터 센다)를 지킨다.
- `alarmTriggers(rec, from, to)`: 알림의 울릴 때들. 걸리는 날 D와 미리 알림 a마다 D - a일의 `time`. 완료면 없다.
- `countdownStatus(rec, today)`: 반복이 없으면 그날과의 차이(지났으면 음수), 반복이 있으면 오늘이나 그 뒤의 가장 가까운 날과의 차이. 생일은 그해 나이(`date`의 해부터 센다).
- 울리는 것의 이름: `<id>@<걸린 날>@<미리 일수>`. 기기마다 울린 이름을 기억해 두 번 울리지 않는다.

## 7. 화면

### 7.1 편집 화면 (웹앱과 PC 앱이 같이 쓴다)

```
[취소]   11월 20일 금요일   [저장]
          음 10.11 · 공휴일
┌────────────────────────────────┐
│ ⏰ 09:00 회의   ⏳ 시험 3일 남음 │  ← 그날의 알림·카운트다운 띠(없으면 숨김, 누르면 편집)
├────────────────────────────────┤
│ 메모 (고른 배경색이 바탕에 보인다) │
│                                │
├────────────────────────────────┤
│ [✓ 완료] [● 배경] [⏰ 알림] [⏳ 카운트다운] │
└────────────────────────────────┘
```

- `완료`: 지금 줄(또는 고른 줄들)의 `[+]`를 켜고 끈다. 설정의 편집 완료 알람이 켜져 있으면 소리를 낸다.
- `배경`: 단추 위에 색 상자가 뜬다(없음 + 22색 + 지금 색이 목록 밖이면 그 색). 고르면 바로 메모 칸 바탕과 단추의 점이 그 색이 되고 상자가 닫힌다. 바깥을 누르거나 Esc를 누르면 닫힌다.
- `알림`, `카운트다운`: 편집 화면 위에 작은 시트가 뜬다(7.2). 띠의 항목을 눌러도 같은 시트가 그 항목을 열고 뜬다.
- 저장과 취소는 지금처럼 메모와 배경색에만 적용한다. 알림과 카운트다운은 그 시트의 `저장`으로 바로 저장된다.
- 폰에서 글자판이 열리면 도구 단추는 글자판 바로 위에 온다(시트가 보이는 영역을 따라간다).

### 7.2 알림과 카운트다운 시트

- 알림: 글(비우면 메모의 첫 줄), 시각(`<input type="time">`, 오늘이면 지금+15분을 15분 단위로 내린 시각, 다른 날이면 09:00), 미리 알림(당일, 하루 전, 이틀 전, 사흘 전, 5일 전, 일주일 전 중 1~5개, 기본 당일), 반복(안 함, 매일, 근무일, 매주, 매달, 매년, 음력 매년)과 끝(계속, 날짜까지, 횟수), 완료. 단추: 삭제(있는 항목만), 취소, 저장. 아이폰에서는 아래에 "아이폰 알림은 Scriptable 위젯 스크립트가 예약합니다" 안내와 `지금 예약` 단추(`scriptable:///run/CalendarFIF?schedule=1`)를 둔다.
- 카운트다운: 글, 유형(기본, 생일, 기념일, 명절, 시험), 반복(안 함, 매년, 음력 매년; 생일과 기념일과 명절은 기본이 매년), 달력 아래에 표시(기본 켬), 완료. 단추는 알림과 같다.
- 글이 비었고 메모도 비었으면 저장할 수 없다("글을 적어 주세요").

### 7.3 달력

- 칸: 그날 걸린 알림과 카운트다운을 메모 줄 앞에 한 줄씩 적는다. 알림은 종 표시와 (설정이 켜져 있으면) 시각, 카운트다운은 모래시계 표시(생일은 케이크). 완료한 것은 취소선. 메모 줄과 같은 줄 수 제한에 든다.
- 달력 아래 줄: `달력 아래에 표시`가 켜진 카운트다운 중 완료하지 않은 것을 가까운 순서로 "글 3일 남음", "글 오늘", "글 2일 지남"으로 보인다(생일은 "글(43살) 12일 남음"). 없으면 줄을 숨긴다. 폰에서는 옆으로 밀어 본다. 누르면 그 카운트다운의 날짜 편집 화면을 연다.
- 쪽 서명에 알림·카운트다운 자료의 판 번호를 넣는다. 자료가 바뀌면 붙어 있는 쪽을 다시 그린다(드문 일이다).

### 7.4 설정

- 웹앱: `셀` 묶음을 새로 만들고 다음을 둔다. `줄 머리`(지금 `보기`에 있는 것을 옮김), `셀 간격`(좁게 1px, 보통 2px, 넓게 4px; 기본 좁게 = 지금), `줄 간격`(좁게, 보통, 넓게; 기본 보통 = 지금의 줄 높이), `완료된 작업 표시`, `완료 작업 맨 아래로`(옮김), `알림 시각 표시`(기본 켬), `편집 완료 알람`(없음, 짧은 소리; 기본 없음), `리마인드 알람`(없음, 차임, 벨; 기본 차임). 바꾸면 `소리`는 한 번 들려준다.
- PC 앱: `셀` 쪽에 `알림 시각 표시`와 `리마인드 알람`을 더한다.

## 8. 울리기

- **웹앱과 PC 앱 화면(공통, `src/web/alarmClock.ts`):** 다음 울릴 때를 계산해 그때 깨는 타이머를 건다. 자료가 바뀌거나 화면이 다시 보이거나 1분마다 다시 계산한다(잠자기 뒤 늦은 타이머). 울릴 때가 지났어도 10분 안이면 울리고, 그보다 오래된 것은 울리지 않는다. 울린 이름은 `calfif.alarmsFired`에 30일 동안 둔다.
- **웹앱:** 화면 위쪽에 알림 상자(시각, 글, `확인`)를 띄우고 리마인드 알람 소리를 낸다. 아이폰은 사용자가 화면을 한 번이라도 누른 뒤에만 소리가 난다.
- **PC 앱:** 화면이 메인 프로세스에 알리면 메인이 작은 창(테두리 없음, 맨 위, 작업 영역의 오른쪽 아래)을 띄워 울린 것들을 쌓아 보이고 소리를 낸다. `확인`을 누르면 닫힌다. 달력 창의 순서 처리와 Windows 기능 호출에는 손대지 않는다.
- **아이폰(앱이 닫혀 있을 때):** 위젯 스크립트가 돌 때마다(위젯이 새로 그려질 때, 스크립트를 열 때) 알림 문서를 읽어 앞으로 7일의 울릴 때를 가까운 것부터 48개까지 Scriptable `Notification`으로 예약한다. 이름이 `calfif:`로 시작하는 예약 중 목록에 없는 것은 지운다. 위젯 안에서 예약이 안 되면 조용히 넘어가고, 스크립트를 열면 예약하고 몇 개를 예약했는지 알린다. 주소에 `schedule=1`이 있으면 예약만 하고 끝낸다. 알림을 누르면 그날의 편집 화면이 열린다.

## 9. 소리

`src/web/tones.ts`에서 WebAudio로 합성한다: `done`(지금 PC의 짧은 소리), `chime`(세 음), `bell`(종). PC의 `tone.ts`는 이것을 쓰도록 옮긴다.

## 10. 시험과 배포

- 단위 테스트: 반복과 울릴 때와 남은 날, 문서 읽기와 쓰기, 저장소의 보내지 않은 변경, 편집 화면의 도구 단추와 색 상자와 시트, 달력 칸과 아래 줄, 설정, 알림 시계(가짜 타이머), 위젯 예약(가짜 Scriptable).
- 에뮬레이터: 새 규칙(본인만, 꺼진 사용자 막힘, 다른 문서 이름 막힘).
- 실제 터치 확인(`test:touch`): 새 편집 화면에서 배경 고르기, 알림과 카운트다운 만들기, 달력 아래 줄. PC 앱 시험(`desktop:smoke`)에 알림 창이 뜨고 닫히는 `alarm`을 더한다.
- 배포: 규칙 → 2분 뒤 웹앱. 위젯의 동작이 바뀌므로 버전을 0.7.0으로 올린다(사용자는 위젯 스크립트를 다시 복사해야 아이폰 알림이 예약된다). PC 앱 0.7.0을 꾸린다.

## 11. 작성자가 정한 것 (틀렸을 때의 비용)

1. 타이머는 DesktopCal의 카운트다운으로 봤다. → 사용자가 초시계나 뽀모도로를 말한 것이라면 다시 만들어야 한다.
2. 아이폰 알림은 Scriptable 예약에 기댄다. → 위젯이 새로 그려지기 전에 만든 알림은 스크립트를 열거나 `지금 예약`을 누르기 전까지 아이폰에 예약되지 않는다. 위젯 안에서 예약이 안 되는 것으로 드러나면 스크립트를 열어야만 예약된다.
3. 알림과 카운트다운은 메모의 저장과 따로 바로 저장된다. → 편집 화면에서 `취소`를 눌러도 알림은 남는다.
4. 반복은 7가지만 둔다(분기, 매월 말일, 법정 근무일, 에빙하우스, 사용자 정의 간격은 없다). → 필요하면 `freq`에 더한다.
5. 2월 29일의 매년은 윤년에만, 없는 날의 매달과 음력 매년은 건너뛴다. → DesktopCal과 다를 수 있다.
6. 늦은 알림은 10분까지만 울린다. → 기기가 꺼져 있던 동안의 알림은 놓친다.
7. 알림은 기기마다 울린다(한 기기에서 확인해도 다른 기기에서도 울린다). → 같은 알림을 PC와 아이폰에서 두 번 본다.
8. 카운트다운의 지난 날은 "N일 지남"으로 적는다(DesktopCal은 "경과"). → 글만 바꾸면 된다.
9. 셀 간격과 줄 간격의 값은 웹 화면에 맞게 정했다(DesktopCal의 범위를 모른다).
10. 편집 완료 알람의 기본은 없음, 리마인드 알람의 기본은 차임이다.
