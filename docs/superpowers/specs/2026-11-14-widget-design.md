# ② 단계 설계: 아이폰 홈 화면 위젯 (Scriptable)

작성: 2026-11-14. 기준은 승인된 설계(`2026-11-13-calendar-sync-design.md`)의 8.2절이다. 이 문서는 그 절을 만들 수 있을 만큼 자세히 적은 것이고, 새로 정한 것은 9절에 모았다. 사용자는 위젯을 알아서 진행하라고 했다("이제 위젯도 알아서 진행해").

## 1. 목표와 하지 않는 것

목표

- W1. 아이폰 홈 화면의 큰 위젯에 이번 달이 보인다: 월 이름, 요일 줄, 주 단위 줄, 칸마다 날짜와 옅은 배경색과 메모 2~3줄. 오늘을 강조하고 완료한 줄은 취소선으로 그린다.
- W2. 설치는 복사해서 붙여 넣기 한 번이다. 웹앱 설정 화면의 단추가 스크립트를 복사한다. 스크립트에는 공개 설정(프로젝트 주소 등)만 들어가고 비밀번호는 들어가지 않는다.
- W3. Scriptable 안에서 처음 실행하면 이메일과 비밀번호를 묻고, 갱신 토큰만 아이폰 키체인에 둔다.
- W4. 읽기에 실패하면 마지막으로 받은 내용을 "오프라인" 표시와 함께 보여 준다. 로그인 전이면 로그인 방법을 안내한다.
- W5. 위젯을 누르면 웹앱이 열린다.
- W6. 아이폰이 없는 이 PC에서 위젯 그림을 미리 본다(지어낸 자료). 사용자가 PC에서 모바일 화면을 확인하고 싶어 한다.
- W7. 관리자가 추가한 다른 사용자도 자기 계정으로 같은 위젯을 쓴다.

하지 않는 것

- 위젯 안에서 편집(iOS가 허용하지 않는다).
- 즉시 갱신. 갱신 시점은 iOS가 정한다(보통 15~60분).
- 잠금 화면 위젯, 아이패드 전용 크기.
- 위젯에서 홈 화면 웹앱을 여는 것. iOS는 주소로 홈 화면 웹앱을 열 수 없어서 Safari가 열린다.

실패로 보는 것

- 스크립트나 저장소에 비밀번호, 실제 메모, 실제 프로젝트 설정이 들어간다.
- 위젯이 오류를 삼키고 빈 화면만 보인다(무엇이 잘못됐는지 위젯에 글로 보여야 사용자가 알려 줄 수 있다).

## 2. 구성

| 부분 | 위치 | 하는 일 |
|---|---|---|
| 기본 부품 그리기 | `src/widget/tree.ts`, `src/widget/renderTree.ts` | 기본 그리기다. 달 자료와 크기를 받아 글자와 칸을 쌓는 나무를 만들고(순수 함수), 그것을 Scriptable의 위젯 부품(`ListWidget`, `WidgetStack`, `WidgetText`)으로 만든다. |
| 그림 그리기 | `src/widget/scene.ts`, `src/widget/render.ts` | 위젯 매개변수에 `image`가 있을 때 쓴다. 달 자료와 크기, 밝기를 받아 그릴 목록(사각형, 글자, 선)을 만들고(순수 함수), `DrawContext`로 그림 한 장을 그린다. |
| Scriptable 연결 | `src/widget/main.ts` | 로그인, 토큰 갱신, 문서 읽기, 마지막 자료 보관, 매개변수에 따라 기본 부품이나 그림으로 위젯 만들기, 오류 위젯, 위젯 내놓기. |
| 묶음 | `scripts/build-widget.ts` | 위의 것들을 가져오기 없는 자바스크립트 파일 하나로 묶는다(`public/widget/calendarfif-widget.js`, git에 올라가지 않는다). 설정 자리는 표시로 남긴다. |
| 웹앱 설정 | `src/web/ui/widgetInstall.ts` | "위젯 스크립트 복사" 단추와 설치 순서. 설정 화면이 열릴 때 스크립트를 받아 표시를 지금 앱의 공개 설정으로 바꿔 둔다. |
| PC 미리 보기 | `scripts/widget-preview.ts` | 같은 그릴 목록을 헤드리스 Edge의 캔버스에 그려 그림 파일로 만든다. |

웹앱은 스크립트를 품지 않는다. 묶은 파일은 `npm run widget:build`가 `public/widget/`에 만들고, 웹앱 빌드가 그것을 그대로 내놓는다(`/widget/calendarfif-widget.js`). 그래서 묶음이 웹앱 빌드보다 먼저 만들어져야 한다. `npm run build`가 먼저 묶음을 만들고, `npm run deploy`는 `npm run build`를 부른다. 설정 화면은 열릴 때 이 주소에서 스크립트를 받아 설정 자리를 지금 앱의 공개 설정으로 채워 둔다. 단추를 누르면 채워 둔 글을 복사한다(클립보드 쓰기는 누르는 순간에 시작해야 하기 때문이다).

## 3. 위젯이 하는 일 (실행 순서)

1. 키체인에서 갱신 토큰을 찾는다(키 `calendarfif.refreshToken`).
2. 없으면: 앱 안에서 실행 중이면 이메일과 비밀번호를 묻고 로그인한다(`accounts:signInWithPassword`). 받은 갱신 토큰과 계정 ID를 키체인에 둔다. 위젯으로 실행 중이면 "Scriptable에서 이 스크립트를 한 번 실행해 로그인하세요"를 그린다.
3. 갱신 토큰으로 ID 토큰을 받는다(`securetoken.googleapis.com/v1/token`).
4. 이번 달 문서를 읽는다: `firestore.googleapis.com/v1/projects/<프로젝트>/databases/(default)/documents/users/<uid>/months/<YYYY-MM>`. 달의 첫 주와 마지막 주에 걸친 앞뒤 달 날짜는 번호만 흐리게 그리고 메모는 그리지 않는다(문서 1개만 읽기 위해서다).
5. 받은 자료를 Scriptable의 파일(`calendarfif-cache.json`)에 둔다. 읽기에 실패하면 이 파일의 자료를 "오프라인" 표시와 함께 그린다.
6. 크기(`config.widgetFamily`)에 맞게 위젯을 만든다. 기본은 기본 부품으로 그린다. Parameter에 `image`가 있으면 그림 한 장으로 그린다. 다음 갱신 희망 시각을 15분 뒤로 알린다(2026-11-17부터 5분 뒤: `src/widget/refresh.ts`).
7. 토큰이 거절되면(비밀번호 변경, 사용 중지) 갱신 토큰을 지우고 2번의 안내를 그린다.
8. 예상하지 못한 오류는 위젯에 "오류"와 그 내용(28자씩 5줄까지, 마지막 줄에 스크립트의 버전)을 그린다. 오류 위젯을 그리지 못하면 다른 방식으로, 그것도 안 되면 글자만 있는 위젯으로 오류 내용을 보인다.

앱 안에서 실행하면 로그인 뒤 큰 위젯 미리 보기를 띄운다. 메뉴로 "로그아웃"(토큰 지우기)도 고를 수 있다. 메뉴 제목에는 스크립트의 버전과 만든 날짜가 보인다. 미리 보기 중에 저장된 로그인이 거절되면 안내 대신 바로 로그인을 묻는다(한 실행에 한 번).

## 4. 크기별 모양

- 큰 위젯(필수): 위에 "2026년 11월"과 갱신 상태(오프라인일 때만), 요일 줄, 그 아래 5~6주. 칸: 날짜 숫자(일요일 빨강, 토요일 파랑, 오늘은 강조 동그라미), 배경색(옅게), 메모 줄. 줄 수는 5주면 3줄, 6주면 2줄. 넘치는 줄은 마지막 줄을 "+N"으로 바꾼다. 완료한 줄은 흐리게 한다. 기본 부품에서는 앞에 `✓`를 붙이고, 그림 방식에서는 취소선을 긋는다.
- 중간 위젯: 이번 주 한 줄(7칸), 칸마다 메모 4줄.
- 작은 위젯: 오늘 날짜와 요일, 오늘의 메모 5줄.
- 밝기: 기본 부품은 화면 밝기를 스스로 따라간다. 위젯 설정의 Parameter에 `light`나 `dark`를 적으면 고정한다. 그림 방식은 그리는 순간의 값(적었으면 그것, 아니면 기기의 어두운 화면 여부)을 쓴다.
- 색은 웹앱과 같은 값(밝은 화면, 어두운 화면)을 쓴다.

글자 폭을 재는 기능이 Scriptable에 없어서, 취소선 길이와 글자 줄임은 글자 수로 어림한다(한글과 한자는 글자 크기만큼, 영문과 숫자는 0.6배). 기본 부품에서는 메모를 줄마다 한 줄짜리 글로 둔다. 실제 폭이 어림보다 좁으면 iOS가 글자를 10%까지 줄이고, 그래도 넘치면 "…"로 자른다. 다음 줄로 접히지 않는다.

## 5. 웹앱 쪽

- 설정 화면의 "위젯" 칸: "위젯 스크립트 복사" 단추와 설치 순서(Scriptable 설치, 새 스크립트에 붙여 넣기, 한 번 실행해 로그인, 홈 화면에 큰 위젯 추가, 위젯을 길게 눌러 스크립트 고르기).
- 복사가 막힌 브라우저에서는 글 상자에 스크립트를 보여 주고 직접 복사하게 한다.
- PC 앱의 설정에는 넣지 않는다(아이폰에서 복사해야 한다).
- 날짜 주소(`#YYYY-MM-DD`)로 바로 연 편집 화면을 취소한 뒤 뒤로 가기를 하면 편집 화면이 다시 열리던 문제를 고친다(① 단계에서 미뤄 둔 것).

## 6. 보안

- 스크립트에 들어가는 것: 프로젝트 ID, 웹 API 키, 웹앱 주소. 모두 웹앱이 이미 공개하는 값이다. 저장소에는 표시(`__PROJECT_ID__` 등)만 있다.
- 비밀번호는 로그인 요청에만 쓰고 어디에도 두지 않는다. 키체인에는 갱신 토큰과 계정 ID만 둔다.
- 위젯은 읽기만 한다. 쓰는 요청을 보내지 않는다.
- 보안 규칙은 그대로다. 위젯도 그 계정의 권한으로만 읽는다.

## 7. 시험

- 그리기 계산의 단위 시험: 5주와 6주 달, 오늘 강조, 배경색, 완료 줄, 넘치는 줄, 세 크기, 밝기 둘.
- 가짜 Scriptable 환경에서의 시험(Node): 로그인 전 안내, 로그인, 토큰 갱신, 문서 읽기, 실패 때 보관한 자료와 "오프라인", 거절된 토큰 처리, 오류를 위젯에 그리기. 네트워크는 에뮬레이터(Auth 9095, Firestore 8085)의 같은 주소 모양으로 실제 요청을 보낸다.
- 묶음 검사: 만들어진 파일에 `import`/`export`/`require`가 없고, 표시가 남아 있고, 문법이 맞는다. 만든 파일을 가짜 Scriptable(로그인 전, 위젯으로 실행)에서 한 번 실행해, 오류 없이 위젯 하나를 두고 끝나는지와 그 위젯에 로그인 안내("로그인이 필요합니다")가 보이는지 본다. 하나라도 아니면 묶기가 실패한다.
- PC 미리 보기 그림(밝은 화면, 어두운 화면, 세 크기)을 만들어 눈으로 본다.
- 아이폰에서의 실제 동작(Scriptable 버전, iOS 26, 실제 갱신 간격)은 이 PC에서 볼 수 없다. 사용자가 설치해서 확인한다.

## 8. 사용자가 할 일

1. 아이폰에 Scriptable 설치(무료).
2. 웹앱(아이폰) 설정에서 "위젯 스크립트 복사".
3. Scriptable에서 새 스크립트를 만들어 붙여 넣고 한 번 실행해 로그인.
4. 홈 화면에 Scriptable 큰 위젯을 추가하고 그 스크립트를 고른다.

## 9. 작성자가 정한 것 (사용자가 바꿀 수 있다)

| 정한 것 | 이유 | 틀렸을 때 |
|---|---|---|
| 위젯을 누르면 Safari에서 달력이 열린다(날짜 편집 화면이 아니라 달력) | iOS는 홈 화면 웹앱을 주소로 열 수 없다. Safari는 로그인이 따로라 처음 한 번 로그인해야 한다 | 위젯에서 바로 편집으로 가고 싶으면 주소에 오늘 날짜를 붙이면 된다 |
| 앞뒤 달의 날짜는 번호만 그린다 | 갱신마다 문서 1개만 읽는다 | 달의 처음과 끝 주에 걸친 다른 달 메모가 위젯에 안 보인다 |
| 중간과 작은 위젯도 만든다 | 설계가 빌더에게 맡겼고, 같은 그리기 계산으로 적은 비용에 된다 | 쓰지 않으면 그만이다 |
| 기본 부품(글자와 칸을 쌓는 방식)으로 그리고, 그림 한 장 방식은 Parameter의 image로 고른다 | 그림은 밝은 화면과 어두운 화면을 스스로 따라가지 못하고, 위젯의 정확한 크기를 알아야 한다 | 기본 방식의 줄 맞춤이 아이폰에서 어긋날 수 있다. Parameter에 image dark나 image light를 적으면 그림 방식이 된다 |
| 그림 방식의 밝기는 그리는 순간의 기기 설정을 따른다 | 그림은 스스로 색을 바꾸지 못한다 | 밝기를 바꾼 직후 다음 갱신까지 이전 색으로 보인다 |
| 완료한 줄은 취소선 대신 앞에 ✓를 붙인다 | 한글 위의 취소선 글자가 네모로 나올 수 있고 아이폰에서 확인하지 못했다 | 위젯의 완료 줄이 웹앱과 다르게 보인다 |
| 잠깐 거절당했을 때(요청이 많음, 서버 오류)는 로그인을 지우지 않는다 | 일시적인 거절로 로그아웃되면 다시 로그인해야 한다 | 취소된 로그인이 예상 밖의 답으로 오면 "오프라인"이 계속 보인다 |
| 스크립트에 버전과 만든 날짜를 적는다 | 붙여 넣은 것이 어느 것인지 알아야 한다 | 없다 |
