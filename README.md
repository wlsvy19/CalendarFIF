# CalendarFIF

Windows PC와 아이폰에서 날짜별 메모와 날짜 배경색을 양방향으로 동기화하는 개인용 달력이다. 바탕화면 달력 DesktopCal을 대체한다. 이 저장소에는 동기화 핵심, 웹앱, DesktopCal 가져오기, PC 바탕화면 앱, 아이폰 위젯(Scriptable 스크립트)이 들어 있다.

## 처음 준비

1. `npm install`을 실행한다.
2. Firebase 프로젝트를 만든다. 순서는 [docs/firebase-setup.md](docs/firebase-setup.md)를 따른다.
3. `.env.example`을 `.env.local`로 복사하고 `VITE_FIREBASE_*` 네 값과 `OWNER_UID`를 채운다. `.env.local`은 커밋하지 않는다. 비밀번호는 어떤 파일에도 적지 않는다.
4. `VITE_FORCE_LONG_POLLING=1`은 실시간 연결이 되지 않는 네트워크에서 쓴다. 다른 기기의 변경이 몇 초 안에 오지 않을 때 켠다.

## 개발과 테스트

| 명령 | 하는 일 |
|---|---|
| `npm run dev:emu` | 에뮬레이터에 예시 데이터를 넣고 로컬 앱을 띄운다. |
| `npm test` | 단위 테스트를 돌린다. |
| `npx tsc --noEmit` | 타입을 검사한다. |
| `npm run test:emu` | 에뮬레이터로 규칙과 동기화 테스트를 돌린다. |
| `npm run mobile` | 폰 크기 창으로 실제 웹앱을 연다. 처음에는 그 창에서 로그인한다. 이미 열려 있으면 그 창을 닫고 새로 연다. |
| `npm run mobile:emu` | 에뮬레이터와 예시 자료로 폰 크기 창을 연다. |
| `npm run test:touch` | 실제 터치 입력으로 달 넘기기와 날짜 열기를 확인한다. 웹앱의 터치 동작을 고친 뒤에는 배포 전에 돌린다. |
| `npm run test:users` | 에뮬레이터와 지어낸 계정으로 사용자 추가를 처음부터 끝까지 폰 크기 화면에서 실제 터치와 입력으로 확인한다. 관리자의 추가, 사용 중지, 재설정 메일, 지우기, 새 사용자의 로그인과 메모, 비밀번호 변경, 메모를 적는 중에 중지될 때, 중지와 허가 없음 안내를 본다. 로그인, 설정, 사용자 관리 화면을 고친 뒤에는 배포 전에 돌린다. |
| `npm run dev:desktop-emu` | 에뮬레이터에 예시 데이터를 넣고 PC 앱 화면을 브라우저에서 띄운다. |
| `npm run desktop:emu` | 에뮬레이터에 붙여 PC 앱을 Electron으로 띄운다(시험용 계정으로 자동 로그인). |
| `npm run desktop:smoke` | PC 앱을 에뮬레이터에 붙여 자동으로 점검하고 결과를 `build/desktop-smoke/`에 적는다. PowerShell에서 `$env:CALFIF_SMOKE='attach'; npm run desktop:smoke`처럼 환경 변수로 `attach`(기본), `bounds`, `tray`, `settings`, `e2e` 중 하나를 고른다. |
| `npm run desktop:pack:emu` | 에뮬레이터용으로 꾼 앱을 `build/release-emu/`에 만든다. 실제 프로젝트에는 붙지 않고 Windows 시작 시 실행도 걸지 않는다. |
| `npm run desktop:pack:check` | 위에서 꾼 앱을 시험 실행으로 점검한다. `$env:CALFIF_SMOKE='e2e'; npm run desktop:pack:check`로 돌리면 에뮬레이터에서 한 편집이 5초 안에 오가는지까지 본다. |

폰 크기 창은 터치 입력을 흉내 낸 Chromium(Edge)이다. 아이폰 Safari 자체, 아이폰 키보드, 홈 화면에 추가한 앱은 아이폰에서만 확인할 수 있다. 폰 크기 창(Edge)과 아이폰은 넘기는 느낌이 다르다. 부드러운 정도는 아이폰에서 봐야 한다.

에뮬레이터에는 Java 21 이상이 필요하다. PC의 Java가 더 낮으면 `npx tsx scripts/jdk.ts`가 JDK 21을 `.tools/`에 내려받는다.

## 배포

처음 한 번은 저장소 폴더에서 `npx firebase use --add`를 실행해 목록에서 내 프로젝트를 고르고, 별칭을 물으면 `default`를 입력한다. 이 단계가 커밋하지 않는 `.firebaserc`를 만든다. 먼저 `npx firebase login`을 해 두어야 한다([docs/firebase-setup.md](docs/firebase-setup.md) 5단계).

`npm run deploy`는 웹앱을 빌드하고, `OWNER_UID`로 보안 규칙을 만들고, 호스팅과 규칙을 배포한다. 배포가 끝나면 앱은 `https://<프로젝트 ID>.web.app`에 있다.

- 배포는 이 명령으로만 한다. 다른 명령이 `dist/`와 `build/firestore.rules`에 에뮬레이터용 빌드와 시험용 UID를 남겨 둘 수 있기 때문이다.
- `OWNER_UID`가 비어 있거나 시험용 UID이면 규칙 빌드가 오류로 멈춘다.

## DesktopCal 기록 가져오기

| 명령 | 하는 일 |
|---|---|
| `npm run import -- --preview` | 읽고 변환한 결과만 보여 준다. 클라우드에 접속하지 않는다(기본). |
| `npm run import -- --preview --show <YYYY-MM-DD>` | 그 날짜의 변환 결과를 화면에 보여 준다. 여러 번 줄 수 있다. |
| `npm run import -- --upload` | 바뀐 날짜를 클라우드에 올리고 대조한다. 먼저 `클라우드에 올릴까요? (y/N)`를 묻고, `--yes`를 붙이면 묻지 않는다. |
| `npm run import -- --follow` | 올린 뒤 DesktopCal 파일을 지켜보며 바뀔 때마다 올린다. 끝내려면 Ctrl+C를 누른다. 올리기 전에 같은 질문을 하고, `--yes`로 건너뛴다. |

- 가져오기는 DesktopCal 데이터 파일(`%APPDATA%\CalendarTask\Db\calendar.db`)의 복사본만 읽고, 원본에는 쓰지 않는다.
- 내 PowerShell이나 Windows 터미널에서 실행한다. 비밀번호를 가려서 입력받고(`CALFIF_EMAIL`, `CALFIF_PASSWORD` 환경 변수가 있으면 그 값을 쓴다), `--show`는 메모 내용을 화면에 출력한다.
- 첫 `--upload`는 웹앱이나 아이폰에서 아무것도 고치기 전에 한다. 상태 파일이 없는 첫 가져오기에서는 양쪽에 있고 내용이 다른 날짜를 합치지 않고 나중에 고친 쪽으로 정한다.
- 미리 보기에서 `수정 시각 범위`가 달력을 실제로 쓴 연도와 맞는지 확인한다.
- `--upload` 뒤 대조 줄이 `다름 0`, `클라우드에 없음 0`이어야 한다. 아니면 보고서에 해당 날짜가 나온다.
- `--upload`가 오류로 멈추면 DesktopCal에서 그 날짜들을 고치기 전에 바로 다시 실행한다.
- 상태 파일 `%LOCALAPPDATA%\CalendarFIF\import-state.json`은 지난번에 가져온 내용을 기억한다. 지우지 않는다. 지우면 줄 단위 병합이 날짜 전체에서 나중에 고친 쪽을 택하는 방식으로 바뀐다.
- 지난번에 가져온 날짜가 DesktopCal에서 한꺼번에 사라지면 클라우드에서 지우지 않고 멈춘다. `--upload --allow-deletes`로 한 번 확인해 준다. 수동 `--upload`는 사라진 날짜가 10일 이상이면서 지난번 가져온 날짜의 10%를 넘을 때 멈추고, `--follow`는 비율과 상관없이 10일 이상이면 멈춘다. 두 경우 모두 지난번 가져온 날짜가 3일 이상인데 전부 사라져도 멈춘다.

## 전환 기간에 지킬 점

PC에서 DesktopCal을 아직 주로 쓰는 동안 `--follow`는 DesktopCal에서 CalendarFIF 쪽으로만 복사한다. 아이폰이나 웹앱에서 고친 내용은 DesktopCal에 나타나지 않는다. 양쪽에서 같은 날을 고치면 CalendarFIF에서 줄 단위로 합쳐진다.

전환하는 날에는 follow가 마지막 변경까지 올렸는지 확인하고, DesktopCal을 끝내 자동 시작에서 뺀 뒤 follow를 멈춘다.

## 아이폰에서 쓰기

Safari에서 주소를 열고 로그인한 뒤 공유 버튼으로 홈 화면에 추가한다. 홈 화면 앱은 Safari와 로그인 상태를 따로 가지므로 한 번 더 로그인한다. 연결이 끊긴 동안 고친 내용은 `오프라인 (대기 n건)`으로 표시되고 연결이 돌아오면 올라간다.

- 날짜 칸의 숫자 옆에 음력이 작게 나온다(`10.5`, 윤달은 `윤6.1`). 공휴일과 대체공휴일은 숫자가 빨갛고 이름이 숫자 아래에 나온다. 화면이 좁거나 주 번호를 켜서 음력이 칸에 다 들어가지 않으면 그 달의 음력을 더 작게 적고, 그래도 안 들어가는 칸은 음력을 비운다.
- 날짜를 누르면 편집 화면이 올라온다. 제목 아래에 그날의 음력과 공휴일 이름이 나온다.
- 편집 화면과 설정 화면은 손가락으로 아래로 끌어 내리면 닫힌다. 편집 화면은 고친 것이 있으면 저장하고 닫는다. 고친 것을 버리려면 `취소`를 누른다. 긴 메모나 설정 목록을 아래로 내려 둔 상태에서는 그 내용을 끌면 닫히지 않고 스크롤된다. 그때는 위에 붙어 있는 제목 줄을 잡고 끌면 닫힌다.

### 설정

달력 위의 톱니바퀴를 누르면 설정이 열린다. 고르면 바로 바뀐다.

| 칸 | 항목 | 하는 일 |
|---|---|---|
| 화면 | 밝기 | `자동`은 아이폰의 밝은 화면과 어두운 화면을 따른다. `밝게`와 `어둡게`는 한쪽으로 고정한다. |
| 화면 | 색상 | 단추와 오늘 표시의 색. 여덟 가지다. |
| 달력 | 음력 | 날짜 칸과 편집 화면에 음력을 적는다. |
| 달력 | 공휴일 | 공휴일과 대체공휴일을 빨간 날로 표시하고 이름을 적는다. |
| 달력 | 주 번호 | 주마다 왼쪽에 그해의 몇째 주인지 적는다. |
| 달력 | 한 주의 시작 | 일요일 또는 월요일. |
| 메모 | 글자 크기 | 날짜 칸 안 메모의 글자 크기. 크게 하면 한 칸에 보이는 줄이 줄어든다. |
| 메모 | 완료한 줄 보이기 | 끄면 완료 표시한 줄을 날짜 칸에서 숨긴다(편집 화면에는 그대로 있다). |
| 메모 | 완료한 줄을 아래로 | 완료한 줄을 안 끝낸 줄 뒤에 보여 준다. |
| 메모 | 줄 머리 기호 | 줄 앞에 숫자나 점을 붙인다. |

이 설정은 그 기기의 브라우저에만 저장된다. Safari와 홈 화면 앱은 저장소가 따로라서 각각 고른다. 다른 기기와 PC 앱에는 옮겨지지 않는다(PC 앱에는 자기 설정 화면이 있다). 그 아래의 계정, 동기화, 비밀번호, 위젯, 로그아웃은 전과 같다.

## 아이폰 위젯

아이폰의 Scriptable 앱으로 홈 화면에 달력을 띄운다. 큰 위젯은 이번 달, 중간 위젯은 이번 주, 작은 위젯은 오늘을 보여 준다. 메모와 색은 웹앱과 같은 것이다. 공휴일과 대체공휴일은 숫자가 빨갛고 이름이 한 줄 나오며, 날짜마다 음력이 작게 나온다.

### 설치

웹앱의 설정(아이폰에서 연 달력의 설정)에 `위젯` 칸이 있다. 거기서 스크립트를 복사한다. 주소와 프로젝트 정보가 이미 채워져 있다.

1. App Store에서 Scriptable을 설치합니다(무료).
2. 설정의 "위젯 스크립트 복사" 단추로 스크립트를 복사합니다.
3. Scriptable을 열고 오른쪽 위 +를 눌러 새 스크립트를 만든 뒤 붙여 넣습니다. 이름을 CalendarFIF로 바꿉니다.
4. ▶를 눌러 한 번 실행하고, 이 달력에 쓰는 이메일과 비밀번호로 로그인합니다. 비밀번호는 저장되지 않습니다.
5. 홈 화면의 빈 곳을 길게 누른 뒤 왼쪽 위의 "편집" → "위젯 추가"(예전 iOS에서는 +)를 눌러 Scriptable의 큰 위젯을 추가합니다.
6. 추가한 위젯을 길게 눌러 "위젯 편집"에서 Script를 CalendarFIF로 고릅니다.

복사 단추가 막히면 설정에 글 상자가 나온다. 길게 눌러 전체 선택한 뒤 복사한다.

### 알아 둘 것

- 위젯이 언제 새로 그려지는지는 아이폰이 정한다. 보통 15~60분마다다.
- 위젯을 누르면 Safari에서 달력이 열린다. Safari에서도 한 번 로그인해야 한다.
- 위젯에서는 편집할 수 없다. 편집은 달력에서 한다.
- 로그아웃은 Scriptable에서 스크립트를 실행해 "로그아웃"을 고른다.
- 비밀번호를 바꾸면 위젯이 다시 로그인을 요구한다.
- 색은 아이폰의 밝은 화면과 어두운 화면을 따라간다.
- 밝기를 한쪽으로 고정하려면 Parameter에 `light`나 `dark`를 적는다.
- 음력을 빼려면 Parameter에 `nolunar`를 적는다. 여러 개는 띄어 쓴다(예: `dark nolunar`).
- 위젯은 웹앱의 설정(밝기, 색상, 음력 등)을 따르지 않는다. Parameter로만 바꾼다.
- 스크립트가 새로 나오면(위젯에 새 기능이 생기면) 웹앱 설정의 위젯 칸에서 다시 복사해, Scriptable에서 CalendarFIF 스크립트를 열고 내용을 모두 지운 뒤 붙여 넣는다. 로그인은 그대로 남는다. 새로 정해진 선거일과 임시공휴일은 다시 복사하지 않아도 공휴일 자료로 하루 안에 나온다(0.6.0부터, 아래 "공휴일 자료 받아 오기 준비"를 마친 뒤).
- 오류가 나오거나, 비어 보이거나, 모양이 어긋나 보이면 "위젯 편집"의 Parameter에 `image dark` 또는 `image light`를 적는다. 그림 방식으로 그린다.
- 로그인 정보(갱신 토큰)는 Scriptable의 키체인에 있다. Scriptable에 넣은 다른 스크립트도 그것을 읽을 수 있으니 믿을 수 없는 스크립트는 넣지 않는다.
- 로그인한 뒤에 Scriptable에서 스크립트를 실행하면 메뉴가 뜨고, 그 제목에 버전과 만든 날짜가 보인다. 새 스크립트로 바꿨는지 확인할 때 본다. 스크립트의 넷째 줄에도 같은 것이 적혀 있다.

### 개발

- `npm run widget:build`: 스크립트를 만든다(`public/widget/calendarfif-widget.js`, git에 없다). `npm run build`와 `npm run deploy`가 먼저 이것을 해서 배포에 늘 새 스크립트가 들어간다.
- `npm run widget:preview`: PC에서 위젯 모양을 그림으로 본다(`build/shots/widget-*.png`).
- 설계: [아이폰 위젯 설계](docs/superpowers/specs/2026-11-14-widget-design.md)

## 음력과 공휴일

웹앱, PC 앱, 위젯이 같은 계산(`src/core/lunar.ts`, `src/core/holidays.ts`)을 쓴다.

- **음력**은 표로 계산한다. 한국천문연구원 기준 자료이고 양력 1900-01-31부터 2050-12-31까지다. 그 밖의 날짜에는 음력과 설날, 부처님오신날, 추석이 나오지 않는다. 표의 출처는 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)에 있다.
- **공휴일**은 「관공서의 공휴일에 관한 규정」을 따른다. 신정, 설날 연휴, 3.1절, 노동절(2026년부터), 어린이날, 부처님오신날, 현충일, 제헌절(2026년부터), 광복절, 추석 연휴, 개천절, 한글날, 성탄절이다. 일요일은 따로 표시하지 않는다(요일 색이 이미 빨갛다).
- **대체공휴일**은 규정 제3조대로 해마다 계산한다. 설날과 추석 연휴는 일요일과 겹칠 때, 그 밖의 대상 공휴일은 토요일이나 일요일과 겹칠 때, 그리고 평일에 공휴일 둘이 겹칠 때 다음의 첫 번째 비공휴일이 대체공휴일이 된다. 신정과 현충일은 대체하지 않는다. 제도가 넓어진 해(2014, 2021, 2023, 2026년)를 따르므로 지난 달력도 그때와 같다. 1998년 이전의 달력은 그때의 공휴일과 다를 수 있다(1월 2일 등은 따지지 않는다).
- **선거일과 임시공휴일**은 계산하지 않는다. `src/core/holidays.ts`의 `ONE_OFF` 표에 적힌 날(2010년의 것부터 2028-04-12 제23대 국회의원 선거까지)은 늘 나오고, 그 밖에 새로 정해지는 날은 아래의 공휴일 자료로 받는다.
- **공휴일 자료.** GitHub Actions의 `공휴일 자료 갱신`(`.github/workflows/holidays.yml`)이 매일 03:23(한국 시각)에 공공데이터포털의 「한국천문연구원_특일 정보」에서 올해와 다음 해의 공휴일을 달마다 받아(`scripts/fetch-holidays.mjs`), 이 저장소의 `holiday-data` 가지에 `holidays.json` 파일 하나로 올린다. 웹앱, PC 앱, 위젯은 그 파일을 하루에 한 번 읽어 이 기기에 저장해 두고, 계산한 공휴일에 없는 날(새 임시공휴일, 선거일 등)을 더한다. 그래서 새 임시공휴일이 정해져도 배포, 위젯 스크립트 다시 복사, PC 앱 다시 꾸리기가 필요 없다. 공공데이터포털에 실리면 다음 날 새벽에 파일이 바뀌고, 앱은 그 뒤 하루 안에 읽는다.
  - 둘 다 있는 날은 앱의 이름(`설날 연휴`, `3.1절`, `대체공휴일` 등)을 쓰고, 자료에만 있는 날은 자료의 이름을 쓴다(`1월1일`은 `신정`, `기독탄신일`은 `성탄절`, `삼일절`은 `3.1절`, `대체공휴일(…)`은 `대체공휴일`로 적는다). 계산한 날은 자료에 없어도 빼지 않는다. 자료가 늦게 고쳐져도 실제 공휴일이 사라지지 않게 하려는 것이다.
  - 파일 주소를 넣지 않았거나(아래 준비 전), 파일을 읽지 못하거나, 파일이 잘못됐으면 마지막으로 받아 둔 것을 쓰고, 그것도 없으면 계산한 공휴일과 `ONE_OFF` 표만 쓴다. 받지 못하면 웹앱과 PC 앱은 한 시간 뒤에, 위젯은 6시간 뒤에 다시 읽는다.
- 2027년의 대체공휴일은 우주항공청의 「2027년 월력요항」(2026-06-29)과, 2014~2026년은 실제 대체공휴일과 같은지 테스트(`src/core/holidays.test.ts`)가 확인한다. 2028년 이후는 지금의 규정을 그대로 적용한 결과다. 규정이 바뀌면 고쳐야 한다.

### 공휴일 자료 받아 오기 준비

한 번만 하면 된다. 하지 않아도 앱은 전처럼 동작한다(계산한 공휴일과 `ONE_OFF` 표만 쓴다). 돈이 드는 것은 없다. 공공데이터포털의 인증키는 무료이고, 공개 저장소의 GitHub Actions도 무료다. 인증키는 GitHub의 비밀값에만 두고 저장소, 앱, 위젯 스크립트에는 넣지 않는다.

1. **공공데이터포털에서 인증키를 받는다.**
   1. `https://www.data.go.kr`에 로그인한다. 계정이 없으면 오른쪽 위의 `회원가입`으로 만든다.
   2. 첫 화면의 검색 칸에 `특일 정보`를 적고 검색한다.
   3. 결과의 `오픈 API` 목록에서 `한국천문연구원_특일 정보`를 누른다.
   4. 그 화면의 `활용신청` 단추를 누른다. `활용목적`은 자유롭게 적는다(예: `개인 달력에 공휴일 표시`). 다른 칸은 그대로 두고 아래의 신청 단추를 누른다.
   5. 위쪽의 `마이페이지`로 간다. `데이터활용` → `Open API` → `활용신청 현황`에서 `한국천문연구원_특일 정보`를 누르면 `일반 인증키`가 보인다. `Encoding`과 `Decoding` 두 가지가 있는데 어느 것을 써도 된다. 하나를 복사해 둔다. 같은 화면에 활용 기간(끝나는 날)도 나온다.
2. **GitHub에 인증키를 넣는다.**
   1. GitHub에서 이 저장소의 첫 화면을 연다.
   2. 위쪽 탭의 `Settings`를 누른다(저장소 주인에게만 보인다).
   3. 왼쪽 메뉴에서 `Secrets and variables`를 펼치고 `Actions`를 누른다.
   4. `New repository secret` 단추를 누른다.
   5. `Name`에 `DATA_GO_KR_KEY`를 적고, `Secret`에 1에서 복사한 인증키를 붙여 넣는다. `Add secret`을 누른다. 넣은 값은 다시 보이지 않는다(바꿀 때는 그 줄의 연필 단추로 새 값을 넣는다).
3. **처음 한 번 돌려 본다.**
   1. 저장소 위쪽의 `Actions` 탭을 누른다. 워크플로를 켜라는 안내가 나오면 켜는 단추를 누른다.
   2. 왼쪽 목록에서 `공휴일 자료 갱신`을 누른다.
   3. 오른쪽의 `Run workflow`를 누르고, 펼쳐진 상자의 초록 `Run workflow`를 한 번 더 누른다.
   4. 몇 초 뒤 목록에 새 실행이 생긴다. 1분쯤 뒤 초록 체크가 되면 성공이다. 저장소 첫 화면에서 가지 고르기 단추(`main`이라고 적힌 것)를 누르면 `holiday-data`가 생겨 있고, 그 안에 `holidays.json`이 있다.
   5. 빨간 X이면 그 실행을 누르고 `update`를 누른 뒤, 빨간 단계(보통 `특일 정보 받기`)를 펼쳐 마지막 줄들을 본다.
      - `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`나 `HTTP 401`, `HTTP 403`: 키를 아직 쓸 수 없거나 키가 틀렸다. 새로 받은 키는 쓸 수 있기까지 한 시간쯤 걸릴 수 있다. 한 시간 뒤에 3번을 다시 한다. 그래도 같으면 비밀값을 1의 다른 꼴(`Encoding`이었으면 `Decoding`)로 바꿔 넣고 다시 돌린다.
      - `DEADLINE_HAS_EXPIRED_ERROR`: 활용 기간이 끝났다(아래).
      - 그 밖의 것(`HTTP 500` 등): 공공데이터포털이 잠시 안 되는 것일 수 있다. 다음 날 새벽에 저절로 다시 돈다.
      - 비밀값이 없으면 `특일 정보 받기`에 건너뛴다는 한 줄이 나오고 초록으로 끝난다. 이때는 2를 확인한다.
   6. 그 뒤로는 매일 03:23(한국 시각)에 저절로 돈다. GitHub의 예약 실행은 몇 분에서 수십 분 늦게 시작할 수 있다. 내용이 바뀐 날에만 `holiday-data`에 올리고, 바뀐 것이 없어도 7일마다 한 번 빈 커밋을 올린다. 공개 저장소에 60일 동안 활동이 없으면 GitHub가 예약 실행을 멈추기 때문이다. 그래도 멈췄으면 `Actions` → `공휴일 자료 갱신`에서 `Enable workflow`를 누른다.
4. **앱에 파일 주소를 넣고 한 번만 다시 내보낸다.**
   1. `.env.local`에 한 줄을 더한다. `<GitHub 계정>`과 `<저장소>`는 이 저장소 주소 `https://github.com/<GitHub 계정>/<저장소>`의 두 부분이다.
      ```
      VITE_HOLIDAY_URL=https://raw.githubusercontent.com/<GitHub 계정>/<저장소>/holiday-data/holidays.json
      ```
   2. 브라우저로 그 주소를 열어 `"version": 1`로 시작하는 글이 보이는지 확인한다.
   3. 웹앱을 배포한다(`npm run deploy`). 위젯은 설정의 위젯 칸에서 스크립트를 다시 복사해 Scriptable의 스크립트를 바꾼다(메뉴 제목의 버전이 `0.6.0`으로 바뀐다). PC 앱은 `npm run desktop:pack`으로 다시 꾸리고 새 폴더의 `CalendarFIF.exe`를 실행한다. 이 셋은 이번 한 번뿐이고, 그 뒤로는 새 공휴일 때문에 다시 할 일이 없다.

**인증키에는 기한이 있다.** 공공데이터포털의 인증키는 정해진 기간 동안만 쓸 수 있다(끝나는 날은 마이페이지의 활용신청 현황에 나온다). 기간이 끝나면 매일의 작업이 빨간 X로 실패하고(GitHub 알림 설정에 따라 메일이 오기도 한다), 앱들은 마지막으로 받아 둔 자료와 계산한 공휴일로 계속 동작한다. 끝나기 전에 마이페이지에서 연장을 신청하거나, 새로 받은 키로 2의 비밀값을 바꾼다.

## 사용자 추가 (관리자)

관리자는 다른 사람을 사용자로 추가할 수 있다. 추가한 사용자는 각자 자기 달력을 쓴다. 웹앱, 아이폰 홈 화면 앱, PC 앱이 관리자와 똑같이 동작한다.

### 관리자

관리자는 `.env.local`의 `OWNER_UID`에 적힌 계정이다. 지금 로그인해서 쓰는 그 계정이고, 한 명뿐이다. 배포한 뒤 그 계정으로 한 번 로그인하면 관리자 표시가 저절로 만들어진다. 따로 할 일은 없다. 새 보안 규칙은 배포 뒤 1분쯤 지나야 모든 요청에 닿으므로, 그 사이에 로그인하면 잠깐 `이 계정은 사용 허가를 받지 않았습니다.`가 보일 수 있다. 앱이 스스로 다시 확인하므로 기다리거나 안내의 `다시 확인`을 누르면 달력으로 돌아간다.

관리자로 로그인하면 설정에 `사용자 관리` 단추가 보인다. 로그인 직후에는 확인이 끝날 때까지 1~2초쯤 보이지 않을 수 있다. 확인이 끝나면 열어 둔 설정에도 저절로 나타난다. PC 앱에서는 설정의 계정 쪽에 있다. 꾸려 둔 PC 앱은 새로 꾸려야(`npm run desktop:pack`) 사용자 관리와 비밀번호 변경이 보인다. 그 전에 꾸린 앱에는 없다.

### 사용자 추가하기

1. 설정 → `사용자 관리`를 누른다.
2. 아래 칸에 새 사용자의 이메일과 처음 비밀번호(8자 이상)를 적는다.
3. `추가`를 누른다. `추가했습니다.`가 나오고 목록에 `사용 중`으로 보인다.

추가하는 동안 관리자의 로그인은 그대로다. 이미 있는 이메일이면 그 계정의 비밀번호를 넣어야 다시 등록된다(목록에서 지운 사람을 다시 넣을 때가 그렇다).

### 새 사용자에게 알려 줄 것

- 주소: `https://<프로젝트 ID>.web.app`
- 이메일과 처음 비밀번호
- 로그인한 뒤 설정 → `비밀번호 변경`에서 자기 비밀번호로 바꿀 것
- 아이폰이면 Safari에서 주소를 열고 공유 버튼으로 홈 화면에 추가할 것([아이폰에서 쓰기](#아이폰에서-쓰기))
- 앱에서는 관리자도 그 사람의 메모를 볼 수 없지만, Firebase 프로젝트의 주인은 Firebase 콘솔에서 모든 데이터를 볼 수 있다는 것([메모를 볼 수 있는 사람](#메모를-볼-수-있는-사람))

Windows PC에서도 쓰는 사용자에게는 꾸린 폴더(`release\<버전>\CalendarFIF-win32-x64`)를 통째로 건네면 된다. 받은 사람은 그 폴더를 원하는 곳에 두고 `CalendarFIF.exe`를 실행해 자기 이메일과 비밀번호로 로그인한다([꾸리기](#꾸리기)).

### 목록의 단추

- `사용 중지`: 그 사람의 화면에 달력 대신 `관리자가 이 계정의 사용을 중지했습니다.`가 나온다. 편집 화면을 열어 둔 채였으면 저장하거나 취소한 뒤에 나온다. 아직 올리지 못한 편집은 그 기기의 브라우저 저장소에 남는다. 안내에 그 건수가 나오고, 그 상태로 로그아웃을 누르면 한 번 더 묻는다. 저장소를 쓸 수 없는 브라우저(Safari에서 쿠키를 모두 막았을 때 등)에서는 창을 닫을 때까지만 남는다.
- `다시 허용`: 다시 쓸 수 있다. 남아 있던 편집이 그때 올라간다.
- `재설정 메일`: 그 사람의 메일로 비밀번호를 다시 정하는 링크를 보낸다. Firebase가 보내는 메일이라 스팸함에 들어갈 수 있다. 로그인 화면의 `비밀번호를 잊었습니다`도 같은 메일을 보낸다(이메일 칸을 먼저 채운다).
- `지우기`: 한 번 더 누르면(`정말 지우기`) 목록에서 지운다. 지우는 것은 사용 허가뿐이다. 그 사람의 로그인 계정과 메모는 남는다. 지운 사람이 로그인하면 `이 계정은 사용 허가를 받지 않았습니다.`가 나온다. 안내의 `다시 확인`은 허가를 바로 다시 확인한다(다시 추가했으면 달력이 돌아온다).

관리자 자신은 목록에 `관리자`로 보이고, 중지하거나 지울 수 없다.

사람을 그만 쓰게 할 때는 보통 `사용 중지`를 쓴다. `다시 허용`으로 바로 되돌릴 수 있다. `지우기`로 지운 사람을 다시 넣으려면 추가 칸에 그 사람이 지금 쓰는 비밀번호를 넣어야 한다(처음 비밀번호를 바꿨으면 바꾼 비밀번호).

로그인 계정과 메모까지 없애려면 Firebase 콘솔에서 직접 지운다.

1. **보안**(Security) → **Authentication** → **사용자**(Users) 탭에서 그 이메일의 줄을 찾는다. 그 줄의 **사용자 UID**(User UID)를 적어 둔 뒤 계정을 지운다.
2. **데이터베이스 및 스토리지**(Databases & Storage) → **Firestore**에서 `users` → 적어 둔 UID를 골라 지운다. 그 아래의 `months`(그 사람의 메모)도 함께 지운다.

### 비밀번호를 바꾸거나 재설정하면

비밀번호를 바꾸거나(설정 → `비밀번호 변경`) 재설정 메일로 다시 정하면, 그 계정으로 로그인해 있던 다른 기기(PC 앱, 위젯)와 따라가기(`npm run import -- --follow`)는 새 비밀번호로 다시 로그인해야 한다.

### 메모를 볼 수 있는 사람

앱에서는 사용자끼리 서로의 메모를 볼 수 없고, 관리자도 앱에서는 다른 사람의 메모를 볼 수 없다. 관리자가 앱에서 보는 것은 목록의 이메일과 상태뿐이다. 화면이 아니라 Firebase의 보안 규칙이 막으므로 다른 프로그램으로 Firebase에 직접 요청해도 마찬가지다. 허가받지 않은 계정은 어떤 달력도 읽거나 쓰지 못한다.

다만 Firebase 프로젝트의 주인은 Firebase 콘솔에서 모든 데이터를 볼 수 있다. 콘솔은 보안 규칙을 거치지 않는다. 위에서 메모까지 지울 때 여는 Firestore 화면에서는 모든 사람의 메모가 보인다. 메모는 암호화하지 않는다. 사용자를 추가할 때 이 점을 알려 준다.

### 무료 범위

모두 무료 요금제(Spark) 안에서 한다. 서버 기능(Cloud Functions)이나 결제 수단이 필요 없다. 사용자 한 명이 늘면 그 사람이 달을 넘길 때마다 읽기가 몇 번 늘 뿐이다. 관리자 자신의 읽기는 늘지 않는다. 한도는 [무료 한도](#무료-한도-2026-11-13-확인)에 있다.

## PC 바탕화면 앱

바탕화면에 붙어 다른 창 뒤에 있고 배경이 투명한 달력이다. 아이폰, 웹앱과 같은 Firebase 프로젝트를 쓰므로 한쪽에서 고친 메모와 배경색이 몇 초 안에 다른 쪽에 나타난다. Windows 전용이다.

### 준비와 실행

1. `npm install`을 실행한다. 처음 한 번 `npm run desktop:setup`으로 Electron 실행 파일을 받는다. npm 11은 설치 스크립트를 막으므로 이 단계가 따로 있다.
2. `.env.local`은 웹앱과 같다([처음 준비](#처음-준비)).
3. `npm run desktop`을 실행하면 화면을 빌드하고 앱을 띄운다. 개발용이며 `.env.local`의 실제 프로젝트에 붙는다. 처음에는 로그인 화면이 나온다.

### 꾸리기

`npm run desktop:pack`은 `release/<버전>/CalendarFIF-win32-x64/` 폴더를 만든다(버전은 `package.json`의 `version`, 예: `release/0.5.0/`). 서명은 하지 않고 설치 프로그램도 없다. 새 버전을 꾸리면 새 폴더에 만들어진다. 쓰던 앱을 끄고 새 폴더의 `CalendarFIF.exe`를 실행하면 설정과 로그인은 그대로 이어진다(둘 다 `%APPDATA%\CalendarFIF`에 있다). 같은 버전 폴더의 앱이 실행 중이면 아무것도 지우지 않고 멈춘다.

`release`에는 새 버전만 둔다. 꾸리기가 끝나면 옛 버전의 폴더를 지운다. 다만 실행 중이거나 Windows 시작 프로그램이 가리키고 있는 옛 버전은 지우지 않고 알려 준다(켜져 있는 앱의 폴더를 지우면 앱이 깨지고, 시작 프로그램이 가리키는 폴더를 지우면 다음 로그인 때 달력이 뜨지 않는다). 그때는 쓰던 앱을 끄고 새 폴더의 `CalendarFIF.exe`를 한 번 실행한 뒤 `npm run desktop:clean`을 돌린다. 이 명령은 꾸리지 않고 옛 버전만 지운다. 쓰이고 있는지 확인하지 못하면 아무것도 지우지 않는다.

1. 이 폴더를 원하는 곳(예: `C:\Apps\CalendarFIF`)에 통째로 옮긴다.
2. 그 안의 `CalendarFIF.exe`를 실행한다. 앱은 브라우저와 따로 자기 로그인 화면에서 [docs/firebase-setup.md](docs/firebase-setup.md) 3단계에서 만든 계정의 이메일과 비밀번호로 로그인한다.
3. 첫 실행에서 Windows 시작 시 실행이 켜진다. 다음 로그인부터 저절로 뜬다.

한 번 실행한 뒤에 폴더를 다른 곳으로 옮겨도 된다. 옮긴 곳에서 다음에 실행하면 앱이 Windows 시작 시 실행 항목을 새 자리로 다시 건다. 다시 꾸려서 덮어쓴 경우도 같다.

회사 PC가 서명 없는 실행 파일을 막으면 꾸린 앱은 쓸 수 없다. 그때는 저장소 폴더에서 `npm run desktop`을 실행하는 바로가기를 만들어 쓴다. 이 방식은 Windows 시작 시 실행을 걸지 않으므로 필요하면 이 바로가기를 시작 프로그램 폴더에 직접 둔다.

### 쓰는 법

- 날짜 칸을 두 번 누르면 그 날의 메모를 고치고, 오른쪽 클릭하면 편집, 배경색, 오늘로를 고르는 메뉴가 뜬다. 고치는 동안만 창이 앞에서 입력을 받고, 끝나면 다시 맨 뒤로 내려간다.
- 제목 줄의 메뉴 단추에 오늘로, 설정, 로그아웃 등이 있다. 작업 표시줄 오른쪽 아래(알림 영역)의 CalendarFIF 아이콘을 오른쪽 클릭해도 메뉴가 뜬다.
- 트레이 메뉴: 캘린더 숨기기/보이기, 내용 숨기기/보이기, 맨 위에 보기, 위치 및 크기, 설정, Windows 시작 시 실행, 제품 정보, 닫기.
- 위치 및 크기는 메뉴에서 연 조정 화면에서 끌어 바꾸고 적용을 누르면 저장된다(취소하면 원래대로 돌아간다). 모니터 배치마다 따로 기억한다.
- 설정 창, 메모 편집 창, 사용자 관리 창은 위쪽 제목 줄을 끌어 옮길 수 있다. 달력 창 밖으로는 나가지 않는다. 옮긴 자리는 앱을 끌 때까지 기억한다.
- 단축키는 전역이고 처음에는 꺼져 있다. 설정의 고급 쪽에서 켠다. 기본 조합은 캘린더 숨기기 `Ctrl+Alt+H`, 내용 숨기기 `Ctrl+Alt+F`다.
- 설정은 캘린더, 셀, 글꼴 및 색상, 고급, 계정 다섯 쪽이다. 달력 모양(배치, 색, 투명도 등)은 앱 안의 이 기기 저장소에, 창 위치와 단축키 등 시스템 설정은 `%APPDATA%\CalendarFIF\settings.json`에 있다. 설정은 기기별이고 동기화하지 않는다. 로그인 정보와 오프라인 사본도 앱의 프로필 폴더 `%APPDATA%\CalendarFIF`에 `settings.json`과 함께 있으므로, 이 폴더를 지우면 앱이 로그아웃되고 설정이 처음으로 돌아간다. 에뮬레이터용으로 꾸린 앱을 직접 띄우면 프로필은 `%APPDATA%\CalendarFIF-emu`를 따로 쓴다.
- DesktopCal과 함께 쓰는 동안은 CalendarFIF를 DesktopCal 반대쪽 모니터에 둔다. 위치 및 크기에서 옮긴다.

### 지우는 방법

1. 트레이 메뉴에서 Windows 시작 시 실행을 끈다(Windows 시작 프로그램에 등록된 것이 빠진다).
2. 트레이 메뉴에서 닫기를 누른다.
3. 꾸린 폴더와 `%APPDATA%\CalendarFIF`를 지운다.

### 직접 확인할 것

자동 점검(`desktop:smoke`)은 에뮬레이터에서 창의 상태와 동기화를 확인한다. 눈으로 보는 것은 아래 순서로 한다. 앱을 처음 보는 사람 기준이다.

1. 꾸린 `CalendarFIF.exe`를 실행하고 로그인한다. 달력이 DesktopCal 반대쪽 모니터에 보이면 된다(위치는 4번에서 옮긴다).
2. 붙는 것: 다른 프로그램 창을 열면 달력이 그 창 뒤로 가려지고, Win+D를 눌러도 달력이 남는다. 작업 표시줄과 Alt+Tab 목록에는 CalendarFIF가 없다. 메모를 고치거나 설정, 로그인, 위치 및 크기 화면을 여는 동안에도 작업 표시줄 단추는 생기지 않는다.
3. 투명: 바탕화면 그림이 달력 뒤로 비친다. 설정의 글꼴 및 색상 쪽에서 투명도를 움직이면 비치는 정도가 바뀐다.
4. 위치와 크기: 트레이 메뉴의 위치 및 크기를 눌러 끌고 적용을 누른다. 달력이 새 자리와 크기로 남고, 닫았다가 다시 실행해도 같은 자리에 뜬다.
5. 편집: 오늘 칸을 두 번 누르고 한글로 메모를 쓴다. 입력기 후보 창이 글자 근처에 보이고 글자가 입력되면 된다. 칸 밖을 누르거나 편집을 끝내면 창이 다시 다른 창 뒤로 내려간다. 칸에서 오른쪽 클릭으로 배경색을 바꿔 본다.
6. 아이폰과 주고받기: PC에서 고친 메모와 배경색이 5초 안에 아이폰 앱에 나타난다. 아이폰에서 고친 것도 5초 안에 PC 달력에 나타난다. 제목 줄의 상태 글자가 올릴 때 `올리는 중`, 끝나면 `동기화됨`이다.
7. 트레이: 아이콘 오른쪽 클릭 메뉴의 캘린더 숨기기를 누르면 달력이 사라지고, 같은 자리의 캘린더 보이기로 돌아온다. 내용 숨기기는 칸의 글자만 가린다. 맨 위에 보기를 켜면 다른 창 위로 올라오고, 끄면 다시 뒤로 간다.
8. 단축키: 설정의 고급 쪽에서 두 단축키를 켜고 눌러 본다. 다른 프로그램이 같은 조합을 쓰고 있으면 설정 화면에 알림이 나온다.
9. 설정 다섯 쪽: 쪽마다 줄을 바꿔 보고 달력이 바로 따라 바뀌는지 본다. 계정 쪽에서 로그아웃과 로그인이 된다.
10. 시작 시 실행: 트레이 메뉴의 Windows 시작 시 실행에 체크가 있는지 보고, Windows에서 로그아웃했다가 다시 로그인하면 달력이 저절로 뜬다.
11. 아이폰 달 넘기기: 아이폰에서 달을 넘길 때 달력이 손가락을 따라오며 밀려 넘어가는지 본다. 손가락을 멈췄다가 떼도 넘어가는지도 본다.
12. 탐색기 다시 시작: 작업 관리자에서 Windows 탐색기를 다시 시작한다. 8초쯤 안에 달력이 같은 자리에 로그인한 채로 돌아온다.
13. 닫히지 않는 것: 메모를 쓰는 중에 Alt+F4를 눌러도 아무 일도 없다. 창이 닫히지 않고 쓰던 글이 그대로 있다.
14. 글 칸의 오른쪽 클릭: 메모나 로그인의 글 칸에서 오른쪽 클릭하면 메뉴가 뜨지 않는다. 복사와 붙여넣기는 Ctrl+C와 Ctrl+V로 된다.
15. 창 옮기기: 설정 창과 메모 편집 창의 제목 줄을 끌면 창이 따라 움직이고 달력 창 밖으로는 나가지 않는다. 닫았다가 다시 열면 옮긴 자리에 뜬다. 닫기 단추는 그대로 눌린다.
16. 덮인 채로 올라오기: 브라우저 같은 다른 창이 달력을 덮고 있을 때 트레이 메뉴의 맨 위에 보기와 위치 및 크기를 눌러 본다. 달력이 그 창 위로 올라오면 된다. DesktopCal을 켠 채로 한 번, 끈 채로 한 번 본다.
17. 아이폰에서 아래로 끌어 닫기: 날짜를 눌러 편집 화면을 열고 제목 줄이나 빈 곳을 아래로 끈다. 화면이 손가락을 따라 내려오고, 조금만 끌고 놓으면 제자리로 돌아가고, 많이 끌거나 빠르게 튕기면 닫힌다. 메모를 고친 뒤 끌어 닫으면 저장된다. 키보드가 올라와 있을 때도 해 본다. 메모 칸에서 글자를 길게 눌러 커서를 옮기는 것이 전처럼 되는지도 본다. 설정 화면도 끌어 닫힌다.
18. 아이폰의 음력과 공휴일: 날짜 칸에 음력이 숫자 옆에 잘리지 않고 나오는지, 공휴일이 든 달(예: 2026년 10월)에서 숫자가 빨갛고 이름이 숫자 아래에 나오는지 본다.
19. 아이폰의 설정: 설정에서 밝기, 색상, 음력, 공휴일, 주 번호, 한 주의 시작, 글자 크기, 완료한 줄, 줄 머리 기호를 하나씩 바꿔 보고 달력이 바로 따라 바뀌는지 본다. 앱을 닫았다가 열어도 남아 있어야 한다.
20. 위젯의 음력과 공휴일: 설정의 위젯 칸에서 스크립트를 다시 복사해 Scriptable의 스크립트를 바꾼 뒤(메뉴 제목의 버전이 `0.5.0`으로 바뀐다), 위젯에 음력이 나오고 공휴일이 빨간지 본다. 칸이 좁아 음력이 `…`로 잘리거나 모양이 어긋나면 Parameter에 `nolunar`를 적는다.

## 무료 한도 (2026-11-13 확인)

Spark 요금제는 결제 수단이 필요 없다.

- Firestore: 저장 1 GiB, 하루 읽기 50,000회, 쓰기 20,000회, 삭제 20,000회, 나가는 전송 월 10 GiB, 프로젝트당 무료 데이터베이스 1개. 하루 한도는 태평양 시간 자정 무렵에 초기화된다.
- Hosting: 저장 10 GB, 하루 전송 360 MB.
- Authentication: 월간 활성 사용자 50,000명.

한 사람의 달력은 이 한도의 아주 작은 부분만 쓴다. 출처는 `https://firebase.google.com/pricing`과 `https://firebase.google.com/docs/firestore/quotas`다.
