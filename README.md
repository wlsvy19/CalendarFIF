# CalendarFIF

Windows PC와 아이폰에서 날짜별 메모와 날짜 배경색을 양방향으로 동기화하는 개인용 달력이다. 바탕화면 달력 DesktopCal을 대체한다. 이 저장소에는 동기화 핵심, 웹앱, DesktopCal 가져오기, PC 바탕화면 앱이 들어 있고, 아이폰 위젯은 나중에 만든다.

## 처음 준비

1. `npm install`을 실행한다.
2. Firebase 프로젝트를 만든다. 순서는 [docs/firebase-setup.md](docs/firebase-setup.md)를 따른다.
3. `.env.example`을 `.env.local`로 복사하고 `VITE_FIREBASE_*` 네 값과 `OWNER_UID`를 채운다. `.env.local`은 커밋하지 않는다. 비밀번호는 어떤 파일에도 적지 않는다.
4. `VITE_FORCE_LONG_POLLING=1`은 실시간 연결이 되지 않는 네트워크에서 쓴다. 다른 기기의 변경이 몇 초 안에 오지 않을 때 켠다.

## 개발과 테스트

| 명령 | 하는 일 |
|---|---|
| `npm run dev:emu` | 에뮬레이터에 예시 데이터를 넣고 로컬 앱을 띄운다. |
| `npm test` | 단위 테스트를 돌린다. |
| `npx tsc --noEmit` | 타입을 검사한다. |
| `npm run test:emu` | 에뮬레이터로 규칙과 동기화 테스트를 돌린다. |
| `npm run mobile` | 폰 크기 창으로 실제 웹앱을 연다. 처음에는 그 창에서 로그인한다. 이미 열려 있으면 그 창을 닫고 새로 연다. |
| `npm run mobile:emu` | 에뮬레이터와 예시 자료로 폰 크기 창을 연다. |
| `npm run test:touch` | 실제 터치 입력으로 달 넘기기와 날짜 열기를 확인한다. 웹앱의 터치 동작을 고친 뒤에는 배포 전에 돌린다. |
| `npm run test:users` | 에뮬레이터와 지어낸 계정으로 사용자 추가를 처음부터 끝까지 눌러 가며 확인한다. 관리자의 추가와 사용 중지, 새 사용자의 로그인과 메모, 비밀번호 변경, 중지 안내를 본다. 로그인, 설정, 사용자 관리 화면을 고친 뒤에는 배포 전에 돌린다. |
| `npm run dev:desktop-emu` | 에뮬레이터에 예시 데이터를 넣고 PC 앱 화면을 브라우저에서 띄운다. |
| `npm run desktop:emu` | 에뮬레이터에 붙여 PC 앱을 Electron으로 띄운다(시험용 계정으로 자동 로그인). |
| `npm run desktop:smoke` | PC 앱을 에뮬레이터에 붙여 자동으로 점검하고 결과를 `build/desktop-smoke/`에 적는다. PowerShell에서 `$env:CALFIF_SMOKE='attach'; npm run desktop:smoke`처럼 환경 변수로 `attach`(기본), `bounds`, `tray`, `settings`, `e2e` 중 하나를 고른다. |
| `npm run desktop:pack:emu` | 에뮬레이터용으로 꾼 앱을 `build/release-emu/`에 만든다. 실제 프로젝트에는 붙지 않고 Windows 시작 시 실행도 걸지 않는다. |
| `npm run desktop:pack:check` | 위에서 꾼 앱을 시험 실행으로 점검한다. `$env:CALFIF_SMOKE='e2e'; npm run desktop:pack:check`로 돌리면 에뮬레이터에서 한 편집이 5초 안에 오가는지까지 본다. |

폰 크기 창은 터치 입력을 흉내 낸 Chromium(Edge)이다. 아이폰 Safari 자체, 아이폰 키보드, 홈 화면에 추가한 앱은 아이폰에서만 확인할 수 있다. 폰 크기 창(Edge)과 아이폰은 넘기는 느낌이 다르다. 부드러운 정도는 아이폰에서 봐야 한다.

에뮬레이터에는 Java 21 이상이 필요하다. PC의 Java가 더 낮으면 `npx tsx scripts/jdk.ts`가 JDK 21을 `.tools/`에 내려받는다.

## 배포

처음 한 번은 저장소 폴더에서 `npx firebase use --add`를 실행해 목록에서 내 프로젝트를 고르고, 별칭을 물으면 `default`를 입력한다. 이 단계가 커밋하지 않는 `.firebaserc`를 만든다. 먼저 `npx firebase login`을 해 두어야 한다([docs/firebase-setup.md](docs/firebase-setup.md) 5단계).

`npm run deploy`는 웹앱을 빌드하고, `OWNER_UID`로 보안 규칙을 만들고, 호스팅과 규칙을 배포한다. 배포가 끝나면 앱은 `https://<프로젝트 ID>.web.app`에 있다.

- 배포는 이 명령으로만 한다. 다른 명령이 `dist/`와 `build/firestore.rules`에 에뮬레이터용 빌드와 시험용 UID를 남겨 둘 수 있기 때문이다.
- `OWNER_UID`가 비어 있거나 시험용 UID이면 규칙 빌드가 오류로 멈춘다.

## DesktopCal 기록 가져오기

| 명령 | 하는 일 |
|---|---|
| `npm run import -- --preview` | 읽고 변환한 결과만 보여 준다. 클라우드에 접속하지 않는다(기본). |
| `npm run import -- --preview --show <YYYY-MM-DD>` | 그 날짜의 변환 결과를 화면에 보여 준다. 여러 번 줄 수 있다. |
| `npm run import -- --upload` | 바뀐 날짜를 클라우드에 올리고 대조한다. 먼저 `클라우드에 올릴까요? (y/N)`를 묻고, `--yes`를 붙이면 묻지 않는다. |
| `npm run import -- --follow` | 올린 뒤 DesktopCal 파일을 지켜보며 바뀔 때마다 올린다. 끝내려면 Ctrl+C를 누른다. 올리기 전에 같은 질문을 하고, `--yes`로 건너뛴다. |

- 가져오기는 DesktopCal 데이터 파일(`%APPDATA%\CalendarTask\Db\calendar.db`)의 복사본만 읽고, 원본에는 쓰지 않는다.
- 내 PowerShell이나 Windows 터미널에서 실행한다. 비밀번호를 가려서 입력받고(`CALFIF_EMAIL`, `CALFIF_PASSWORD` 환경 변수가 있으면 그 값을 쓴다), `--show`는 메모 내용을 화면에 출력한다.
- 첫 `--upload`는 웹앱이나 아이폰에서 아무것도 고치기 전에 한다. 상태 파일이 없는 첫 가져오기에서는 양쪽에 있고 내용이 다른 날짜를 합치지 않고 나중에 고친 쪽으로 정한다.
- 미리 보기에서 `수정 시각 범위`가 달력을 실제로 쓴 연도와 맞는지 확인한다.
- `--upload` 뒤 대조 줄이 `다름 0`, `클라우드에 없음 0`이어야 한다. 아니면 보고서에 해당 날짜가 나온다.
- `--upload`가 오류로 멈추면 DesktopCal에서 그 날짜들을 고치기 전에 바로 다시 실행한다.
- 상태 파일 `%LOCALAPPDATA%\CalendarFIF\import-state.json`은 지난번에 가져온 내용을 기억한다. 지우지 않는다. 지우면 줄 단위 병합이 날짜 전체에서 나중에 고친 쪽을 택하는 방식으로 바뀐다.
- 지난번에 가져온 날짜가 DesktopCal에서 한꺼번에 사라지면 클라우드에서 지우지 않고 멈춘다. `--upload --allow-deletes`로 한 번 확인해 준다. 수동 `--upload`는 사라진 날짜가 10일 이상이면서 지난번 가져온 날짜의 10%를 넘을 때 멈추고, `--follow`는 비율과 상관없이 10일 이상이면 멈춘다. 두 경우 모두 지난번 가져온 날짜가 3일 이상인데 전부 사라져도 멈춘다.

## 전환 기간에 지킬 점

PC에서 DesktopCal을 아직 주로 쓰는 동안 `--follow`는 DesktopCal에서 CalendarFIF 쪽으로만 복사한다. 아이폰이나 웹앱에서 고친 내용은 DesktopCal에 나타나지 않는다. 양쪽에서 같은 날을 고치면 CalendarFIF에서 줄 단위로 합쳐진다.

전환하는 날에는 follow가 마지막 변경까지 올렸는지 확인하고, DesktopCal을 끝내 자동 시작에서 뺀 뒤 follow를 멈춘다.

## 아이폰에서 쓰기

Safari에서 주소를 열고 로그인한 뒤 공유 버튼으로 홈 화면에 추가한다. 홈 화면 앱은 Safari와 로그인 상태를 따로 가지므로 한 번 더 로그인한다. 연결이 끊긴 동안 고친 내용은 `오프라인 (대기 n건)`으로 표시되고 연결이 돌아오면 올라간다.

## 사용자 추가 (관리자)

관리자는 다른 사람을 사용자로 추가할 수 있다. 추가한 사용자는 각자 자기 달력을 쓴다. 웹앱, 아이폰 홈 화면 앱, PC 앱이 관리자와 똑같이 동작한다.

### 관리자

관리자는 `.env.local`의 `OWNER_UID`에 적힌 계정이다. 지금 로그인해서 쓰는 그 계정이고, 한 명뿐이다. 배포한 뒤 그 계정으로 한 번 로그인하면 관리자 표시가 저절로 만들어진다. 따로 할 일은 없다.

관리자로 로그인하면 설정에 `사용자 관리` 단추가 보인다. 로그인 직후에는 확인이 끝날 때까지 1~2초쯤 보이지 않을 수 있다. 그때는 설정을 닫았다가 다시 연다. PC 앱에서는 설정의 계정 쪽에 있다.

### 사용자 추가하기

1. 설정 → `사용자 관리`를 누른다.
2. 아래 칸에 새 사용자의 이메일과 처음 비밀번호(8자 이상)를 적는다.
3. `추가`를 누른다. `추가했습니다.`가 나오고 목록에 `사용 중`으로 보인다.

추가하는 동안 관리자의 로그인은 그대로다. 이미 있는 이메일이면 그 계정의 비밀번호를 넣어야 다시 등록된다(목록에서 지운 사람을 다시 넣을 때가 그렇다).

### 새 사용자에게 알려 줄 것

- 주소: `https://<프로젝트 ID>.web.app`
- 이메일과 처음 비밀번호
- 로그인한 뒤 설정 → `비밀번호 변경`에서 자기 비밀번호로 바꿀 것
- 아이폰이면 Safari에서 주소를 열고 공유 버튼으로 홈 화면에 추가할 것([아이폰에서 쓰기](#아이폰에서-쓰기))

### 목록의 단추

- `사용 중지`: 그 사람이 로그인하면 달력 대신 `관리자가 이 계정의 사용을 중지했습니다.`가 나온다. 아직 올리지 못한 편집은 그 사람의 기기에 남는다.
- `다시 허용`: 다시 쓸 수 있다. 기기에 남아 있던 편집이 그때 올라간다.
- `재설정 메일`: 그 사람의 메일로 비밀번호를 다시 정하는 링크를 보낸다. Firebase가 보내는 메일이라 스팸함에 들어갈 수 있다. 로그인 화면의 `비밀번호를 잊었습니다`도 같은 메일을 보낸다(이메일 칸을 먼저 채운다).
- `지우기`: 한 번 더 누르면(`정말 지우기`) 목록에서 지운다. 지우는 것은 사용 허가뿐이다. 그 사람의 로그인 계정과 메모는 남는다. 지운 사람이 로그인하면 `이 계정은 사용 허가를 받지 않았습니다.`가 나온다.

관리자 자신은 목록에 `관리자`로 보이고, 중지하거나 지울 수 없다.

로그인 계정과 메모까지 없애려면 Firebase 콘솔에서 직접 지운다.

1. **보안**(Security) → **Authentication** → **사용자**(Users) 탭에서 그 이메일의 줄을 찾는다. 그 줄의 **사용자 UID**(User UID)를 적어 둔 뒤 계정을 지운다.
2. **데이터베이스 및 스토리지**(Databases & Storage) → **Firestore**에서 `users` → 적어 둔 UID를 골라 지운다. 그 아래의 `months`(그 사람의 메모)도 함께 지운다.

### 메모는 서로 볼 수 없다

사용자끼리는 서로의 메모를 볼 수 없다. 관리자도 다른 사용자의 메모를 볼 수 없다. 관리자가 보는 것은 목록의 이메일과 상태뿐이다. 화면이 아니라 Firebase의 보안 규칙이 막는다. 허가받지 않은 계정은 어떤 달력도 읽거나 쓰지 못한다.

### 무료 범위

모두 무료 요금제(Spark) 안에서 한다. 서버 기능(Cloud Functions)이나 결제 수단이 필요 없다. 사용자 한 명이 늘면 그 사람이 달을 넘길 때마다 읽기가 몇 번 늘 뿐이다. 관리자 자신의 읽기는 늘지 않는다. 한도는 [무료 한도](#무료-한도-2026-11-13-확인)에 있다.

## PC 바탕화면 앱

바탕화면에 붙어 다른 창 뒤에 있고 배경이 투명한 달력이다. 아이폰, 웹앱과 같은 Firebase 프로젝트를 쓰므로 한쪽에서 고친 메모와 배경색이 몇 초 안에 다른 쪽에 나타난다. Windows 전용이다.

### 준비와 실행

1. `npm install`을 실행한다. 처음 한 번 `npm run desktop:setup`으로 Electron 실행 파일을 받는다. npm 11은 설치 스크립트를 막으므로 이 단계가 따로 있다.
2. `.env.local`은 웹앱과 같다([처음 준비](#처음-준비)).
3. `npm run desktop`을 실행하면 화면을 빌드하고 앱을 띄운다. 개발용이며 `.env.local`의 실제 프로젝트에 붙는다. 처음에는 로그인 화면이 나온다.

### 꾸리기

`npm run desktop:pack`은 `release/CalendarFIF-win32-x64/` 폴더를 만든다. 서명은 하지 않고 설치 프로그램도 없다.

1. 이 폴더를 원하는 곳(예: `C:\Apps\CalendarFIF`)에 통째로 옮긴다.
2. 그 안의 `CalendarFIF.exe`를 실행한다. 앱은 브라우저와 따로 자기 로그인 화면에서 [docs/firebase-setup.md](docs/firebase-setup.md) 3단계에서 만든 계정의 이메일과 비밀번호로 로그인한다.
3. 첫 실행에서 Windows 시작 시 실행이 켜진다. 다음 로그인부터 저절로 뜬다.

한 번 실행한 뒤에 폴더를 다른 곳으로 옮겨도 된다. 옮긴 곳에서 다음에 실행하면 앱이 Windows 시작 시 실행 항목을 새 자리로 다시 건다. 다시 꾸려서 덮어쓴 경우도 같다.

회사 PC가 서명 없는 실행 파일을 막으면 꾸린 앱은 쓸 수 없다. 그때는 저장소 폴더에서 `npm run desktop`을 실행하는 바로가기를 만들어 쓴다. 이 방식은 Windows 시작 시 실행을 걸지 않으므로 필요하면 이 바로가기를 시작 프로그램 폴더에 직접 둔다.

### 쓰는 법

- 날짜 칸을 두 번 누르면 그 날의 메모를 고치고, 오른쪽 클릭하면 편집, 배경색, 오늘로를 고르는 메뉴가 뜬다. 고치는 동안만 창이 앞에서 입력을 받고, 끝나면 다시 맨 뒤로 내려간다.
- 제목 줄의 메뉴 단추에 오늘로, 설정, 로그아웃 등이 있다. 작업 표시줄 오른쪽 아래(알림 영역)의 CalendarFIF 아이콘을 오른쪽 클릭해도 메뉴가 뜬다.
- 트레이 메뉴: 캘린더 숨기기/보이기, 내용 숨기기/보이기, 맨 위에 보기, 위치 및 크기, 설정, Windows 시작 시 실행, 제품 정보, 닫기.
- 위치 및 크기는 메뉴에서 연 조정 화면에서 끌어 바꾸고 적용을 누르면 저장된다(취소하면 원래대로 돌아간다). 모니터 배치마다 따로 기억한다.
- 단축키는 전역이고 처음에는 꺼져 있다. 설정의 고급 쪽에서 켠다. 기본 조합은 캘린더 숨기기 `Ctrl+Alt+H`, 내용 숨기기 `Ctrl+Alt+F`다.
- 설정은 캘린더, 셀, 글꼴 및 색상, 고급, 계정 다섯 쪽이다. 달력 모양(배치, 색, 투명도 등)은 앱 안의 이 기기 저장소에, 창 위치와 단축키 등 시스템 설정은 `%APPDATA%\CalendarFIF\settings.json`에 있다. 설정은 기기별이고 동기화하지 않는다. 로그인 정보와 오프라인 사본도 앱의 프로필 폴더 `%APPDATA%\CalendarFIF`에 `settings.json`과 함께 있으므로, 이 폴더를 지우면 앱이 로그아웃되고 설정이 처음으로 돌아간다. 에뮬레이터용으로 꾸린 앱을 직접 띄우면 프로필은 `%APPDATA%\CalendarFIF-emu`를 따로 쓴다.
- DesktopCal과 함께 쓰는 동안은 CalendarFIF를 DesktopCal 반대쪽 모니터에 둔다. 위치 및 크기에서 옮긴다.

### 지우는 방법

1. 트레이 메뉴에서 Windows 시작 시 실행을 끈다(Windows 시작 프로그램에 등록된 것이 빠진다).
2. 트레이 메뉴에서 닫기를 누른다.
3. 꾸린 폴더와 `%APPDATA%\CalendarFIF`를 지운다.

### 직접 확인할 것

자동 점검(`desktop:smoke`)은 에뮬레이터에서 창의 상태와 동기화를 확인한다. 눈으로 보는 것은 아래 순서로 한다. 앱을 처음 보는 사람 기준이다.

1. 꾸린 `CalendarFIF.exe`를 실행하고 로그인한다. 달력이 DesktopCal 반대쪽 모니터에 보이면 된다(위치는 4번에서 옮긴다).
2. 붙는 것: 다른 프로그램 창을 열면 달력이 그 창 뒤로 가려지고, Win+D를 눌러도 달력이 남는다. 작업 표시줄과 Alt+Tab 목록에는 CalendarFIF가 없다. 메모를 고치거나 설정, 로그인, 위치 및 크기 화면을 여는 동안에도 작업 표시줄 단추는 생기지 않는다.
3. 투명: 바탕화면 그림이 달력 뒤로 비친다. 설정의 글꼴 및 색상 쪽에서 투명도를 움직이면 비치는 정도가 바뀐다.
4. 위치와 크기: 트레이 메뉴의 위치 및 크기를 눌러 끌고 적용을 누른다. 달력이 새 자리와 크기로 남고, 닫았다가 다시 실행해도 같은 자리에 뜬다.
5. 편집: 오늘 칸을 두 번 누르고 한글로 메모를 쓴다. 입력기 후보 창이 글자 근처에 보이고 글자가 입력되면 된다. 칸 밖을 누르거나 편집을 끝내면 창이 다시 다른 창 뒤로 내려간다. 칸에서 오른쪽 클릭으로 배경색을 바꿔 본다.
6. 아이폰과 주고받기: PC에서 고친 메모와 배경색이 5초 안에 아이폰 앱에 나타난다. 아이폰에서 고친 것도 5초 안에 PC 달력에 나타난다. 제목 줄의 상태 글자가 올릴 때 `올리는 중`, 끝나면 `동기화됨`이다.
7. 트레이: 아이콘 오른쪽 클릭 메뉴의 캘린더 숨기기를 누르면 달력이 사라지고, 같은 자리의 캘린더 보이기로 돌아온다. 내용 숨기기는 칸의 글자만 가린다. 맨 위에 보기를 켜면 다른 창 위로 올라오고, 끄면 다시 뒤로 간다.
8. 단축키: 설정의 고급 쪽에서 두 단축키를 켜고 눌러 본다. 다른 프로그램이 같은 조합을 쓰고 있으면 설정 화면에 알림이 나온다.
9. 설정 다섯 쪽: 쪽마다 줄을 바꿔 보고 달력이 바로 따라 바뀌는지 본다. 계정 쪽에서 로그아웃과 로그인이 된다.
10. 시작 시 실행: 트레이 메뉴의 Windows 시작 시 실행에 체크가 있는지 보고, Windows에서 로그아웃했다가 다시 로그인하면 달력이 저절로 뜬다.
11. 아이폰 달 넘기기: 웹앱을 `npm run deploy`로 다시 배포한 뒤, 아이폰에서 달을 넘길 때 달력이 손가락을 따라오며 밀려 넘어가는지 본다.
12. 탐색기 다시 시작: 작업 관리자에서 Windows 탐색기를 다시 시작한다. 8초쯤 안에 달력이 같은 자리에 로그인한 채로 돌아온다.
13. 닫히지 않는 것: 메모를 쓰는 중에 Alt+F4를 눌러도 아무 일도 없다. 창이 닫히지 않고 쓰던 글이 그대로 있다.
14. 글 칸의 오른쪽 클릭: 메모나 로그인의 글 칸에서 오른쪽 클릭하면 메뉴가 뜨지 않는다. 복사와 붙여넣기는 Ctrl+C와 Ctrl+V로 된다.

## 무료 한도 (2026-11-13 확인)

Spark 요금제는 결제 수단이 필요 없다.

- Firestore: 저장 1 GiB, 하루 읽기 50,000회, 쓰기 20,000회, 삭제 20,000회, 나가는 전송 월 10 GiB, 프로젝트당 무료 데이터베이스 1개. 하루 한도는 태평양 시간 자정 무렵에 초기화된다.
- Hosting: 저장 10 GB, 하루 전송 360 MB.
- Authentication: 월간 활성 사용자 50,000명.

한 사람의 달력은 이 한도의 아주 작은 부분만 쓴다. 출처는 `https://firebase.google.com/pricing`과 `https://firebase.google.com/docs/firestore/quotas`다.
